과거 UI/서비스/설정 파일을 통째 덮거나 새로운 RAG/DSL/트레이스 엔진을 만들지 않는다.

[소스 우선순위]
실제 Desktop canonical 실행 소스와 fresh 테스트 > 현재 madasin.zip > 이 보고서의 구체적 근거 > 과거 src111_mergex15.zip > UAW의 포트폴리오식 서술.

시작 경로는 C:\AbandonWare\demo-1\demo-1\src 이다.
단, 이것을 Gradle root라고 가정하지 말 것. madasin ZIP은 main/java와 main/resources를 가진 소스 스냅샷이며 build.gradle/pom/wrapper/tests가 없다.
실제 build root, sourceSets, mainClass, 배포되는 JAR/정적 리소스 경로를 먼저 확정한다.
이후 이 지시서의 ${SRC}는 “현재 ZIP의 main/가 실제로 매핑되는 부모 디렉터리”, ${BUILD}는 실제 build root, ${TEST_JAVA}는 실제 활성 Java test source root다.
main 경로가 별도 생성/clean 소스로 매핑되면 그 경로를 따르고 원본→생성본의 소유권을 문서화한다. 둘 다 임의 수정하지 않는다.

[절대 보존]
- Java/Spring/LangChain4j의 현재 실제 dependency lock. 이 작업을 빌미로 버전 upgrade 금지.
- 기존 provider/key/env 계약. openssl/opnessl/apikey/시크릿 파일 및 이름·값·포맷을 바꾸거나 출력하지 말 것.
- 현재 preferred/strict/auto 모델 선택, actual model 보고, generationTermination, stop/cancel, exact-run replay/terminal commit.
- 현재 session settings, 첨부 소유권, 기억 scope, GraphRAG source revision/consent, private 자료 격리.
- DOMPurify, raw HTML subscriber projection, snapshot size/field cap, lazy load, AbortController/version guard.
- 현재 정상인 memory-only/empty-context PromptBuilder fallback.
- 기존 task/lease/preflight가 있으면 그것을 사용한다. 이번 작업을 위해 감독 agent나 병렬 work-ledger를 새로 만들지 않는다.

[범위와 작업 방식]
코드 수정은 Desktop의 확인된 canonical source에서만 한다. 외부 조사본/Notebook은 supporting evidence다.
기존 다른 작업의 수정과 uncommitted 변경을 보존한다. 강제 reset/clean/force-push/자동 배포 금지.
한 원인마다 failing test → 최소 patch → 해당 test → 관련 regression 순서.
같은 목표를 두 route/두 facade/두 pipeline에 중복 구현하지 않는다.
판정은 positive(보존), negative(수정), neutral/evidence_needed(런타임 증거 필요)로 나눈다.
이미 해결된 항목은 no-op과 해당 테스트 증거를 기록하고 넘어간다.
