## 0) 한 줄 목표
사용자는 실제로 **클라우드 API 모델을 주로 쓴다.** 이 제품의 주류 경로는 API이고, 로컬 Ollama는 "남는 슬롯이 있을 때만 쓰는 마지막 대체"다. 그래서 /chat의 RAG·챗봇 검증 기준 모델을 **API 모델**로 바꾸고, 로컬 전용 문제에는 시간을 쓰지 않는다.

## 1) 사용자 결정 (원래 목표 문서보다 우선)
- 원래 목표 문서의 "로컬 우선 / 유료 최대 3회"는 **비용 안전장치**였지 제품 방향이 아니었다. 이 보충으로 대체한다.
- Codex가 앞서 "API 우선 제안은 이번 목표의 로컬 우선 범위와 충돌하니 참고만 한다"고 판단한 부분은 **철회**한다. 이번 실행의 검증 기준은 API다.
- 단, 라우팅 순서 자체를 API 우선으로 재배선하는 구현(GPT Pro 분석의 WP1~WP3: `api-routing.yaml` 순서, `llm.provider: local`, `DynamicChatModelFactory.isLocalModel()` 교체, `RoutingProfile` 재배선)은 **이번 작업 범위가 아니다.** 다음 지시서에서 따로 한다. 이번에는 "API 모델로 고르면 RAG·챗봇이 제대로 되나"를 증명하고 고치는 데 집중한다.

## 7) 비용·호출 상한 (이 보충으로 바뀌는 값)
- API 생성 호출: 이번 실행 전체에서 **최대 25회**(A 약 15회, B 약 4회, 여유 6회). 자동 재시도도 1회로 센다. 기존 runner의 실제 생성 요청 수 카운터를 그대로 쓴다.
- 401 / 403 / 429 / 결제·쿼터 오류: 같은 경로에서 재시도 0. 원문을 그대로 보고서 맨 위 `외부 API:`에 적는다. 429는 일시 제한과 쿼터 소진을 구분한다.
- GLM 경로는 이미 HTTP 400(이 계정에서 지원 안 됨)이 났으니 다시 부르지 않는다.
- 공개 URL(`abandonwareai.kro.kr`) 전송 0. 로컬 `127.0.0.1:18180`만 쓴다.
- 서버 재기동은 기존 예산 안에서만 쓴다.
