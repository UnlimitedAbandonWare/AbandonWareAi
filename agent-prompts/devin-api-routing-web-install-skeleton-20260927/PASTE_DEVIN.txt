## 3. Self-Ask (5문 — 시작 전 답하고 진행)

1. **선택 실패의 SSOT는 어디인가?** → 카탈로그(`ChatModelCatalogService` + `app.ai.allow-remote-model-selection` + `remote-model-selection-routes`) vs Admin(`OpenAiModelSelectionPolicy.effectiveAllowRemoteSelection`). 둘이 다르면 UI/설정 불일치.
2. **웹 설치가 지금 없는가?** → 예. in-app web install→route 등록 없음. 카탈로그 recheck는 pull 안 함. 로컬 pull만 `LocalLlmProcessManager` / desktop scripts.
3. **무엇을 새로 만들지 않는가?** → 두 번째 catalog/factory/aspect/OpenRouter runtime. 새 provider client ❌.
4. **allowlist 전략은?** → 전역 `allow-remote=true` 맹목 플립 ❌. 승인된 단일 라우트(예: `api3`) 중심으로 좁게. economy 등 원치 않는 라우트가 같이 열리지 않게 증명 후.
5. **검증 예산은?** → free/local → low_cost → paid. `AWX_AGENT_ALLOW_PAID_MODELS=1` 없으면 유료 soak ❌. RTX 3090 Ollama 로컬 우선.

## 4. Context — 왜 Powerful 모델 선택이 안 되는가 (probe A/B/C/D)

| ID | 원인 | 증거 방향 |
|---|---|---|
| **A** | 카탈로그는 raw `app.ai.allow-remote-model-selection=false` + allowlist `app.ai.remote-model-selection-routes` 기본 **`api3`만** → 대부분 클라우드 행이 `remote_selection_disabled` | GET `/api/chat/models` 응답의 disabled reason |
| **B** | Admin 설정은 `OpenAiModelSelectionPolicy.effectiveAllowRemoteSelection` — `OPENAI_API_KEY` 있으면 true → **UI/설정 vs 카탈로그 불일치** | ModelSettings / Admin effective vs catalog row |
| **C** | Powerful paid 라우트(gpt-5.5/premium, gemini-2.5-pro, Claude 등)가 `manifest` / `llm.yaml`에서 `enabled:false` 이거나 allowlist 밖 | `main/resources/configs/cloud-models.manifest.yaml` (classpath SSOT; **root `configs/cloud-models.manifest.yaml` 은 MISSING일 수 있음**) + `application-llm.yaml` `llmrouter.models.*` |
| **D** | `openai-economy`는 meta-display에는 enabled이나 allowlist 밖. 전역 allow-remote만 켜면 economy도 열림 → **맹목 플립 금지** | meta-display cue ≠ main chat allowlist |
| **E (설치 공백)** | in-app **웹 설치→route 등록 없음**. catalog recheck는 원격 pull 안 함. 로컬만 `LocalLlmProcessManager` / `scripts/ollama-light-preload.ps1` / `data/agent-handoff/model-autopilot/desktop-pull-now-v1/` | 코드 경로 대조 |

추가: Groq 가드는 `GroqFreeTierGuard` — bypass 금지. `data/usage/groq-free-plan.json` 존재 관찰 가능하나 **증거를 날조하지 말 것**.
