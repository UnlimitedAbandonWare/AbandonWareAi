## 6. Gaps / 아쉬운점 T1–T3 (순위 + 증거)

### T1 — 커밋 실패 시 WHY가 불투명 (`selected-*-failed`) — W2 정렬
- `commit_selected`: `git_staged_guard` returncode≠0 또는 `ok:false`여도 가드 JSON의 `reason`/`findings`를 버리고 `selected-staged-scan-failed`만 반환.
- 예외 경로: `selected-commit-failed` + `errorType`만 — safe message/stderr redacted snippet 없음.
- vibe는 `deferred(result["reason"], …, detail=payload)`로 상위 reason만 에이전트 UX에 노출.
- **증거:** `data/agent-handoff/codex-autonomy/devin-safe-git-commit-update-0927-b6f0e3c8/final.json` `failedBatches` 6건 reason ∈ {`selected-staged-scan-failed`,`selected-commit-failed`}만; `progress.json` `failed:6`. scripts 배치에 `__pycache__/*.pyc` 포함돼도 실패 WHY 비가시.
- **선행:** W2 Acceptance(`scanReason`/`errorType`+safe detail, exit 2/3/4 유지, 시크릿 미인쇄).

### T2 — handoff journal ↔ git log 한 줄 링크 부재 (what/why 추적)
- journal은 `taskId`/`purpose`/`plannedScope`/`agent`를 가짐. vibe `--task-id`는 journal `AUTO:*` 노트만 기록.
- `message_ok` LABELS는 Reason/Verify/Constraint만 — **Task-Id / Topic / Session trailer·본문 키 없음**.
- 결과: `git log --oneline --grep=<taskId>` 또는 trailer로 “이 커밋이 어느 handoff/topic인지” 역추적 불가.
- **증거:** 동 handoff `journal.json` (`taskId=devin-safe-git-commit-update-0927-b6f0e3c8`, purpose에 brief 경로) vs 커밋 메시지 규약에 task-id 필드 없음; `agent_git_vibe_commit.py` `journal_note`는 AUTO 한 줄만.

### T3 — `git_doctor` / `git_publish_review`가 vibe deferred/failure에 미부착 (under-used)
- doctor·publish-review는 skill/recipes/tests에만 존재. `agent_git_vibe_commit.orchestrate` deferred 반환 전후 subprocess 호출 없음.
- soft-auto·vibe-workflow: deferred reason 보고 후 stop — `nextOwner`/foreign split/publish verdict를 자동으로 붙이지 않음.
- **증거:** repo 전역 참조가 skill/test/recipes에 편중; vibe 소스에 `git_doctor`/`git_publish_review` 문자열 없음. alike-closet final은 PUBLISH BLOCKED를 journal 서술로만 남김(오케스트레이터 부착 필드 없음).

- **동작:**
  - scan 실패: 가드 stdout JSON에서 `reason`/`findings` **요약만** → `scanReason`(또는 동등) + 선택 `scanFindingsCount`/`blockedPathCount`(경로 해시·rule id만, **시크릿 값·원문 ❌**).
  - 예외: 기존 `errorType` + 짧은 safe message(또는 redacted stderr snippet, 길이 상한).
  - 상위 `reason` 코드 문자열(`selected-staged-scan-failed` / `selected-commit-failed`) **유지**(호환). exit 2/3/4 의미 유지.
- **Acceptance:**
  - [ ] 가드 `ok:false` fixture → 응답에 `scanReason`(동등) 존재, 테스트 단언.
  - [ ] RuntimeError/TimeoutExpired → `errorType` + safe detail; stdout JSON에 시크릿 패턴 문자열 없음.
  - [ ] vibe deferred JSON의 `detail`(또는 동등)에 위 필드 관통.
  - [ ] 기존 성공 경로·exit code 회귀.

### T2 — Journal ↔ git log 링크 (message-file / trailer 규약 + `--task-id` 시임)
- **변경 위치(최소):** `agent_git_vibe_commit` — `--task-id` 있을 때 커밋 메시지에 **trailer 또는 본문 한 줄**로 `Task-Id: <id>`(또는 `AWX-Task-Id:`) 주입; 선택적으로 journal에서 읽은 `topic`/`purpose` 짧은 slug(길이 상한, 시크릿 스크럽). `message_ok`는 기존 LABELS 유지 + trailer는 **추가**이지 대체 아님. skill/workflow에 “grep 가능한 task-id” 한두 문장.
- **동작 원칙:**
  - message-file 원본 손상 최소화: temp message file에 trailer append 후 `-F`로 전달, 또는 커밋 직전 규약 검증.
  - `git log --oneline --grep=Task-Id` / `--grep=<taskId>`로 journal 폴더와 교차 가능.
  - journal 쪽은 기존 `AUTO:committed=<sha>` 유지(이미 있음) — **양방향**: log→taskId, journal→sha.
  - 메시지/trailer/로그에 토큰·경로 시크릿·대화원문 ❌.
- **Acceptance:**
  - [ ] `--task-id foo --dry-run` 계획에 trailer/주입 의도 표시(또는 동등 필드).
  - [ ] fixture 커밋(테스트 repo) 메시지에 `Task-Id: …` 존재; `message_ok` LABELS 여전히 통과.
  - [ ] task-id 없으면 기존 동작 동일(회귀).
  - [ ] 시크릿-like 문자열이 trailer에 들어가지 않음(스크럽 또는 거부).

### T3 — vibe deferred/failure에 doctor·publish-review 자동 부착 (read-only subprocess)
- **변경 위치:** `agent_git_vibe_commit.orchestrate` deferred/failure 반환 직전(성공-only 경로에 push 트리거 ❌); soft-auto/vibe-workflow 한 줄(“deferred 시 doctor 요약 포함”).
- **동작:**
  - deferred/failure 시 `python -B scripts/git_doctor.py --root <repo> --json` (+ 가능하면 `--owned-path` 반복) 호출 → 요약 필드만 부착: `doctor.issues[]` code/`nextOwner`/짧은 detail(상한). 실패·timeout 시 `doctor: {ok:false,reason:…}`로 soft-fail(커밋 deferred reason을 가리지 않음).
  - **publish-review**는 “failure 직후 공개 준비 질문이 의미 있을 때”만(예: 로컬 커밋은 됐으나 후속 publish 판단이 필요한 세션, 또는 deferred reason이 scan/secret/remote 계열). 기본은 **deferred/failure에 doctor 우선**; publish-review는 opt-in 플래그 또는 좁은 reason 화이트리스트. **절대 push하지 않음.**
  - soft-auto 카드/승인 UI 신설 ❌.
- **Acceptance:**
  - [ ] fixture deferred(예: forbidden-path / message-missing / index-lock) → stdout JSON에 `doctor` 요약 키 존재.
  - [ ] doctor subprocess 실패해도 원래 `deferred` reason·exit 유지.
  - [ ] publish-review 호출 경로가 켜져도 verdict만 기록, push/fetch/remote mutate 없음(테스트 단언 또는 코드 경로 검수).
  - [ ] dry-run은 doctor를 **호출하지 않거나** read-only preview만(문서화).

## 11. Report format

끝나면 아래로만 보고:

```
DONE | T1=… T2=… T3=…(SKIP/HOLD 명시) | W-ref: W2-aligned=yes
CHANGED: <paths>
VERIFY: <명령 + exit>
WHY: <scanReason/errorType 필드명 한 줄>
LINK: <trailer 키 이름 + journal AUTO 유지 여부>
ATTACH: <doctor/publish 키 이름 · dry-run 정책>
HARD-STOPS-OK: yes
HOLD: <막힌 이유 코드 | none>
SKIP: <하지 않은 항목 + 이유>
```

상태 키워드: **DONE** / **SKIP** / **HOLD** 중 하나 필수.
