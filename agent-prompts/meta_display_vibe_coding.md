# Meta Display 에이전트 작업 프롬프트

에이전트에게 요구사항을 자연어로 맡기는 바이브 코딩을 전제로 한다. 에이전트의 확신이나 코드 생성량 대신 실행 가능한 수용 조건으로 변경을 끝낸다. 기존 `.agents/skills/demo1-meta-display-webapp/SKILL.md`와 현재 AGENTS의 source-owner 절차를 사용한다.

기본은 **로그인·회원가입·계정/역할 설정 없이 핵심 기능을 바로 실행**하는 것이다. 사용자가 계정 기반 기능을 명시적으로 요청하지 않으면 인증 UI·미들웨어·사용자 테이블·인증 의존성을 자동 생성하지 않는다. 현재 `demo.interview.enabled=true`의 홈페이지와 `/api/chat/sync`, 기존 assist/card 경로를 먼저 재사용한다. 오래된 로그인 템플릿이나 보안 체크리스트만 보고 이 기본값을 해제하거나 로그인 절차를 복구하지 않는다.

## 매 작업에 붙일 입력

```text
목적: <사용자가 겪는 한 가지 문제>
현재 경로: <일반 sync / 휘발성 Conversate / 운영자 카드 전달 중 실제 경로>
재현: <입력, 상태, 동작 순서, 기대 결과>
대상: <현재 source owner의 파일 목록>
수용 조건: <정상 1개, 실패 1개, 늦은 응답/취소 1개>
검증: <기존 집중 검사와 필요한 실제 관측>
한도: <시간, 외부 호출 수, 비용 상한; 미지정 유료 호출 0회>
보존: <기존 사용자 변경, 공개 계약, 자격 증명, 데이터·기능>
```

## 실행 기준

1. 실제 파일·호출자·활성 sourceSet을 먼저 확인한다. 같은 이름의 클래스가 있으면 import와 전체 패키지명을 따라 실제 실행 구현을 구분한다. SDK 기능 부재를 판단하기 전에 현재 고정 버전의 builder와 request parameters를 확인한다. 검색 결과, 과거 PASS, 하위 에이전트 보고는 현재 소스와 충돌하면 재검증한다. 이미 구현된 동작을 새로 만들지 않는다.
2. 한 부모 에이전트가 편집·통합·판정을 소유한다. 독립 탐색은 좁은 경로와 질문 하나를 맡기고 기존 라우팅·GLM 전송 HOLD를 지킨다. 같은 질문을 여러 외부 서비스에 중복 전송하지 않는다.
3. 수정 전 실제 모듈의 의미 있는 실패를 확보한다. 한 원인에 최소 패치를 적용하고 같은 검사를 통과시킨다. 파일 수·라인 수를 점수로 삼지 않되, 설명할 수 없는 변경 파일은 제외한다.
4. 한 논리 질문의 request ID, idempotency, session/epoch/version을 유지한다. 타임아웃은 결과 미확정이다. 자동 재전송·새 키 발급·과거 응답 덮어쓰기로 성공을 만들지 않는다.
5. 일반 `/api/chat/sync`의 대화 보관 정책과 Conversate의 휘발성 음성 경로를 혼동하지 않는다. 음성 전사를 일반 chat으로 우회 저장하거나 카드 ACK를 모델 생성으로 집계하지 않는다.
6. 근거 없음, 충돌, 거절, 대체 응답을 화면에서 구분한다. 출력 원문과 출처는 기존 허용 규칙으로 처리하고 provider ID·내부 경로·비밀 값을 사용자 카드나 보고서에 추가하지 않는다.
7. 앱이 권한·키·모델·기기를 못 쓰면 그 실행 단계만 `evidence_needed`로 남긴다. 핵심 개발 동선에 불필요한 로그인 장벽은 실제 호출 관계를 확인해 제거하되, 익명 대화 소유권·cross-origin/CSRF·비밀/관리 데이터·admission 경계를 무차별 해제하지 않는다. 합성 fixture로 로그인 없는 실행을 검증할 수 있으며 실제 계정 생성이나 유료 호출을 기본 검증 조건에 넣지 않는다. 실제 유료 연결은 선택 제공자·허용 입력·예산이 정해진 뒤 진행한다.
8. 정리는 현재 owner에서 미사용·중복임이 입증된 범위만 수행한다. 서로 역할이 다른 스킬과 API를 이름이 비슷하다는 이유로 합치지 않는다. 보관·복원 경로와 타인의 변경을 유지한다.
9. 완료에는 변경 파일, 실패→통과, 실제 호출 수, 측정 범위, 남은 증거 하나, 이번 preimage/postimage 기반 복구를 남긴다. 테스트나 도구의 연결 성공은 실제 음성·모델·안경 성공이 아니다.

`health`, `modelReady`, 모델 catalog는 준비·발견 증거이며 실제 생성 성공은 같은 요청의 생성 시도와 의미 있는 응답으로 검증한다. 다른 작업이 소유한 Ollama 프로세스의 시작·중지·재시작은 소유자의 명시적 권한이 필요하며, 현재 작업이 시작해 소유한 프로세스만 자체 정리한다.

## 이번에 확인한 경계의 회귀 사례

| 시나리오 | 수용 조건 |
| --- | --- |
| fallback=true 응답이 여러 페이지 | 모든 답변 페이지와 읽기 알림이 대체 응답을 표시; 본문 유지 |
| 정상 응답·model metadata 없음 | 근거 없이 fallback으로 표시하지 않음 |
| RAG 안전·근거 표가 포함된 응답 | 내부 HTML 주석만 숨김; 7단계 공개 정보와 원본 DTO 유지 |
| malformed version/text/expiry | 렌더링·ACK 0회; 다음 정상 snapshot 처리 가능 |
| 빈 카드·만료·이전 버전 | 기존 카드 정리·오래된 응답 억제 유지 |
| timeout 후 Enter 반복 | 같은 입력의 추가 inference 요청 0회 |
| Deepgram 클래스·키만 존재 | 실제 Conversate 호출 경로·응답 시도 없으면 연결 완료 아님 |
| 로컬 Gemma의 reasoning 설정 | 정확한 모델·loopback·기존 플래그 조건; 이미지 배열·토큰 상한·다른 모델 요청 보존 |
| 문장 수 지정이 있는 후속 질문 | 출력 형식만으로 이전 메시지 반복 경로에 진입하지 않음; 명시적 기억 조회는 보존 |
| Display 처리 예산 | 기본 서버 80초·클라이언트 90초 계약과 취소 유지; cold load와 warm 생성 시간을 분리하고 자동 재전송 금지 |
| 직접 Ollama는 성공하고 Spring은 실패 | 같은 시각의 manager 준비 상태·PID·실제 SDK 경로 확인; health나 예산 증가만으로 복구 판정하지 않음 |

## 기본 집중 검증

```powershell
node scripts/meta_display_webapp_contract_tests.cjs
node scripts/display_receiver_rag_contract_tests.cjs
node --test src/test/js/conversate-ui.test.cjs src/test/js/conversate-pcm.test.cjs
```

명령 성공은 해당 클라이언트 범위의 증거다. 변경 경계가 Java·설정·보안으로 확장되면 해당 owner와 회귀 검사를 새로 선언한다. 공식 Simulator와 하드웨어는 실제 관측할 때만 PASS로 기록한다.
