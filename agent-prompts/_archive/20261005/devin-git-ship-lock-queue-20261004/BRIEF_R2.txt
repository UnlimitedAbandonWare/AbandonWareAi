## 0. 한 줄 목표
Git-Ship-Easy(및 git_ship) 실행 시 타 에이전트 작업으로 index.lock이 감지되면 점진적 알림과 함께 안전하게 대기하고, 에이전트가 git 작업을 끝마치면 자동으로 커밋·푸시로 이어지며, 만약 에이전트 비정상 종료 등으로 오래 방치된 고아(stale) 락이 감지되면 프로세스 생존 검사 후 사용자 승인을 거쳐 강제로 락을 해제(Break Lock)하고 권한을 회수하여 계속 진행하는 기능을 구현한다.

## WP2 [DEVIN] 커밋 및 Push 단계의 Lock 대기 자동 재시도 및 연계 (Wait & Ship)
- 증거: `scripts/git_ship_easy.py:521-529`, `scripts/git_ship_easy.py:558-570`
- RED 검사: `test_git_ship_easy.py`에 `cmd_commit` 및 `push_flow` 직전에 index.lock이 걸렸다가 풀렸을 때 중단되지 않고 대기 후 커밋/푸시가 완료되는 시뮬레이션 테스트 추가 -> exit!=0 확인.
- 최소 수정:
  1) `commit_flow`: 미리보기 승인 후 실제 커밋 실행(`git_ship.cmd_commit`) 직전에도 `wait_for_lock(g, out)`을 연동하여, 대기 후 락이 풀리면 바로 커밋 실행.
  2) `push_flow`: 실제 push 실행(`_apply_push`) 직전에도 `wait_for_lock(g, out)`을 연동.
  3) 메뉴 `3. 커밋 + push(올리기)` 선택 시: 에이전트가 git을 다 쓰면 커밋에 이어 push까지 끊김 없이 자동으로 "올리기" 완료.
- 완료 조건: 사용자가 한 번 지시하면 에이전트가 git을 다 쓰는 즉시 커밋(+push)이 안정적으로 완료됨.

## WP3 [DEVIN] 고아(Stale/Orphan) index.lock 감지 및 사용자 확인 강제 해제 (Break Lock)
- 증거: `scripts/git_ship.py:204-216`, `scripts/git_ship_easy.py:232-246`
- RED 검사: `test_git_ship_easy.py`에 방치된 고아 index.lock(예: age 120초 이상, git 프로세스 없음) 상황에서 사용자에게 승인을 묻고, 'y' 입력 시 lock을 안전 삭제 후 작업을 계속 진행하는 테스트 추가 -> exit!=0 확인.
- 최소 수정:
  1) `check_stale_lock(g, threshold_s=90.0) -> dict`:
     - lock 파일의 `ageSeconds`가 기준(예: 90초 이상)을 초과하는지 확인.
     - 현재 OS에서 `git.exe` 프로세스가 실행 중인지 확인 (Windows: `tasklist /FI "IMAGENAME eq git.exe"` 실행하여 활성 프로세스 유무 판정).
     - 실행 중인 `git.exe`가 없다면 `is_orphan=True` 판정.
  2) `wait_for_lock`:
     - 대기 중 고아 락이 감지되거나 타임아웃 도달 시:
       ```
       [경고] index.lock이 {age}초 동안 남아있고, 실행 중인 git.exe 프로세스가 없습니다.
       (에이전트가 비정상 종료되어 락이 해제되지 못했을 수 있습니다)
       고아 락을 강제로 삭제하고 권한을 회수하여 계속 진행할까요? (y/N) 
       ```
     - 사용자가 `y`를 입력하면: `.git/index.lock`을 안전하게 제거(`os.unlink`)하고, "고아 락을 해제했습니다. 작업을 계속 진행합니다." 출력 후 `True` 반환(작업 자동 재개).
     - `N` 입력 또는 취소 시: lock을 유지하고 안전하게 중단 (`False` 반환).
- 완료 조건: 비정상 종료된 에이전트의 잔여 락으로 인한 영구 차단을 사용자가 안전하게 즉시 돌파 가능.
