## WP1 [DEVIN] wait_for_lock 지능형 진행 상황 알림 및 대기 유연화
- 증거: `scripts/git_ship_easy.py:232-246`, `scripts/git_ship.py:45-46`
- RED 검사: `test_git_ship_easy.py`에 lock 대기 시 주기적 진행 메시지(예: "[대기 중 9초 경과] 다른 에이전트 git 작업 중... (취소: Ctrl+C)") 출력 검증 테스트 추가 -> `pytest scripts/test_git_ship_easy.py -k "wait_for_lock_progress"` exit!=0 확인.
- 최소 수정:
  1) `wait_for_lock(g, out=print, sleep=time.sleep, wait_s=None, retries=None, notify_interval_s=6.0)`: 매 경과 시간마다 진행 상태를 `out()`으로 출력하고 `sys.stdout.flush()` 처리.
  2) 대화형 CLI(Git-Ship-Easy)에서는 대기 회수를 충분히(예: 기본 30회 = 90초 대기) 허용하여 타 에이전트 작업 중 섣불리 튕기지 않도록 보강.
- 완료 조건: lock 대기 중 침묵하지 않고 사용자에게 진행 상황을 지속적으로 알리며, lock 해제 시 성공(True) 반환.

## WP2 [DEVIN] 커밋 및 Push 단계의 Lock 대기 자동 재시도 및 연계 (Wait & Ship)
- 증거: `scripts/git_ship_easy.py:521-529`, `scripts/git_ship_easy.py:558-570`
- RED 검사: `test_git_ship_easy.py`에 `cmd_commit` 및 `push_flow` 직전에 index.lock이 걸렸다가 풀렸을 때 중단되지 않고 대기 후 커밋/푸시가 완료되는 시뮬레이션 테스트 추가 -> exit!=0 확인.
- 최소 수정:
  1) `commit_flow`: 미리보기 승인 후 실제 커밋 실행(`git_ship.cmd_commit`) 직전에도 `wait_for_lock(g, out)`을 호출하여, 대기 후 락이 풀리면 바로 커밋 실행.
  2) `push_flow`: 실제 push 실행(`_apply_push`) 직전에도 `wait_for_lock(g, out)`을 호출.
  3) 메뉴 `3. 커밋 + push(올리기)` 선택 시: 에이전트가 git을 다 쓰면 커밋에 이어 push까지 끊김 없이 자동으로 "올리기" 완료.
- 완료 조건: 사용자가 한 번 지시하면 에이전트가 git을 다 쓰는 즉시 커밋(+push)이 안정적으로 완료됨.
