## 3. 항목 (우선순위별 작업 명세)

### WP1. [P0 / 최고 우선순위] FallbackAwareChatModel의 TimeBudget 소진 방지 및 다이나믹 시간 슬라이스 분할
- 대상: `main/java/com/example/lms/llm/gateway/FallbackAwareChatModel.java` 및 `src/test/java/com/example/lms/llm/gateway/FallbackAwareReplaySafetyTest.java`
- 현상: Primary Ollama 요청이 지연될 때 전체 TimeBudget을 100% 소진하여 fallback 모델로 전환될 기회가 차단됨.
- 요구사항:
  1. `FallbackAwareChatModel.doChat` 진입 시 fallback이 구성된 경우, Primary 호출에 할당되는 유효 제한시간을 전체 TimeBudget의 일부(권장 60%)로 슬라이싱.
  2. Primary가 시간 슬라이스 초과 또는 `TIMEOUT_SOFT` 발생 시 즉시 fallback resolver(`qwen3.5:9b`, `gemma4:12b` 등 fast lane)를 동적으로 가동.
  3. `TraceStore`에 `llm.gateway.fallback.timeSliceAllocatedMs` 기록.
- 검증: `.\gradlew.bat test --tests com.example.lms.llm.gateway.FallbackAwareReplaySafetyTest --no-daemon --console=plain` 실행 exit 0 확인.

### WP2. [P1] StrategyConflictResolver의 단일 모드 독점 완화 및 다이나믹 스테이지 힌트 구성
- 대상: `main/java/com/example/lms/orchestration/StrategyConflictResolver.java`, `ExecutionPlan.java`
- 현상: 복수 신호(lowRecall + lowAuthority 등) 발생 시 `EXTREMEZ` 단일 모드만 승리하고 다른 모드가 강제 억제되어 복합 상황 대응력 저하.
- 요구사항:
  1. 신호 결합 양상에 따라 파이프라인 단계 중 불필요한 단계를 스킵하거나 병렬 검증을 여는 동적 힌트(Dynamic Stage Hints)를 `ExecutionPlan` knobs에 반영.
  2. 일반/개념 질의(검색 근거 0건 허용)에서는 불필요한 재시도 없이 빠른 방출(Bypass/Normal)로 즉시 전이되도록 분기 유연화.
- 검증: `.\gradlew.bat test --tests com.example.lms.orchestration.StrategyConflictResolverTest --no-daemon --console=plain` 통과.

### WP3. [P2] 24시간 초과 Stale In-progress Journal 자율 정리 및 DB Lock 복구 일관성 확보
- 대상: `scripts/agent_recovery_status.py`, `scripts/db_agent.py`, `scripts/work_journal.py`
- 현상: 12건 이상의 방치된 고아 저널이 도구 스캔에서 경고를 유발하고, 로컬 DB 락(exit 3) 발생 시 자동 우회 표준화 필요.
- 요구사항:

  2. `db_agent.py`의 `--via auto` 모드가 락 감지 시 실시간 HTTP 레인(`/api/internal/db/meta/*`)으로 실패 없이 매끄럽게 폴백하는지 확인.
- 검증: `python -B scripts/agent_recovery_status.py status` 및 `python -B scripts/test_db_agent.py` 실행 exit 0 확인.
