## 2. 가드레일을 두 종류로 나눈다

### 2.1 반드시 강화할 것: 에이전트의 변경 범위

사용자 승인 없이 다음을 바꾸지 않는다.

- 파이프라인 모듈 구성·단계 순서·호출 인터페이스·빈 등록 범위·실행 진입점.
- 기존 HTTP 경로, 요청 DTO 필드와 의미, SSE 이벤트 계약, 오류·재시도·취소 계약.
- `sessionId`, `ctx.memory`, owner·session·channel·동의 범위와 기억 저장 주체.
- 검색 ON/OFF·심층 검색 의도, 선택 모델의 식별자, 프롬프트 조립 경로, 임베딩 모델·차원·인덱스 구분.
- Java 17·LangChain4j 1.0.1, 기존 프로퍼티·환경변수 이름, 자격 증명 해석 경로.

필요한 기존 메서드의 최소 수정은 허용한다. **기존 코드 수정 금지를 핑계로 동일 역할의 서비스·라우터·검색기·어댑터를 복제하지 않는다.** 파일 개수나 변경 줄 수만으로 안전성을 판단하지 않고 변경된 동작 계약을 확인한다.

금지: 전체 파일 덮어쓰기, 대량 리네이밍, 광역 component scan, 빈 overriding, 새 프레임워크 도입, 이미 수정된 로직 재적용, 실패 테스트 삭제·skip으로 통과 만들기, 승인 없는 테스트 기대값 완화.

### 2.2 그대로 복원하지 않을 것: 구형의 과도한 실행 제한

구형의 인용 개수·품질 점수·로컬 전용·강제 질의 확장 정책은 장점 목록에 자동 포함하지 않는다. UAW의 높은 임계값이나 구형 YAML을 현재 전역값으로 덮어쓰지 않는다.

인증·권한 격리·비밀 보호·사용자 동의·비용 상한·멱등성은 유지한다. 반면 특정 답변을 막는 품질 임계값은 **어느 질문 유형에서 무엇이 실패했는지**를 재현한 뒤 별도 단위로 조정한다. 정상 인사·일반 설명·현재 세션의 사용자 진술에 외부 인용을 억지 요구하지 않는다. 외부 검증이 필요한 질문에서 검색이 실패하면 이를 숨기지 않고 확인된 범위와 근거 부족을 구분한다.

진단 기능 실패는 답변 생성을 불필요하게 막지 않아야 한다. 그렇다고 진단 실패를 성공·저장 완료로 바꾸어 표시해서는 안 된다.

## 4. 역할과 변경 통제

### GPT 프로: 읽기 전용 분석·이식 단위 정의

구형 함수의 입력·출력·부작용을 현재의 같은 역할 구현과 비교한다. 현재 더 나아진 부분을 보호하고, 부족한 동작 하나만 선정한다. 파일 전체가 아니라 메서드·조건·출력 필드·표시 계약 단위로 이식 카드를 작성한다. 모르는 부분을 새 설계로 메우지 않는다. 분석 완료를 소스 구현 완료라고 표현하지 않는다.

### Codex: 선택된 한 단위만 구현

활성 단위의 파일·심볼·설정 키만 수정한다. 기존 보호 테스트와 최소 실패 테스트를 먼저 실행하고, 최소 diff로 통과시킨다. 범위 밖 결함은 메모만 남긴다. 해당 단위의 검증이 끝나면 **사용자 확인 대기**로 종료한다.

### Devin·기타 모델

별도로 구현 담당으로 지정되지 않았다면 조사·반례 검토만 수행한다. 지정되더라도 Codex와 같은 범위·중단 계약을 적용한다. 여러 모델이 같은 원본·같은 단위를 동시에 수정하지 않는다. 어떤 모델도 이식 카드의 허용 범위를 스스로 넓히거나 설계 보존 테스트를 약화할 수 없다.

### 문구만이 아닌 확인 절차

프롬프트만으로 임의 변경을 완전히 막을 수 있다고 주장하지 않는다. 기존 Git·리스·저널·테스트를 사용해 다음을 확인한다.

- 시작 시 실제 Git 루트, `git status --short`, 현재 HEAD, 이미 존재하는 수정·미추적 파일을 기록한다. Git 정보가 없으면 파일 해시 기준을 쓰되 임의 `git init`하지 않는다.
- 활성 단위에는 허용 파일뿐 아니라 **허용 심볼·프로퍼티·금지 계약**을 적는다. 공유 대형 파일 전체를 수정 가능 구역으로 취급하지 않는다.
- 편집 직전 기준 해시·diff가 달라졌으면 해당 부분을 다시 읽는다. 다른 작업을 reset·checkout·덮어쓰기로 제거하지 않는다.
- 완료 전 기준 대비 실제 diff, 신규 파일, 삭제·이동, 테스트/fixture 변경을 검토한다. 테스트 기대값 변경은 사용자 요구에서 유도된 차이만 허용한다.
- 기존 작업 저널에 단위 ID·기준점·판정·다음 확인을 남긴다. 새 잠금 프레임워크·전역 Git 훅·다중 규칙 문서를 의무화하지 않는다.
- 커밋·push·배포는 별도 승인된 범위에서만 수행한다. 작업이 완료됐다는 이유로 자동 커밋하지 않는다.

## 5. 한 번에 하나의 이식 단위

단위는 파일 하나가 아니라 **독립적으로 실패 재현·회귀 검증·되돌림이 가능한 동작 하나**다. 같은 목적에 필수인 설정 두 곳의 정합화는 한 단위일 수 있지만, API 선택 복구와 트레이스 화면 수리는 서로 다른 단위다.

절차:

```text
현재 기준 확인
→ 단일 이식 카드 확정
→ 실패 재현 또는 현재 동작 특성 테스트
→ 최소 수정
→ 해당 회귀 및 영향 범위 검사
→ 사용자 확인 대기
→ 사용자가 승인한 뒤에만 다음 단위 시작
```

상태는 `조사 / 선택 / 수정 / 국소검증 / 사용자확인대기 / 승인 / 보류 / 폐기`로 남긴다. 테스트 통과를 사용자 승인으로 치환하지 않는다. 이미 해결된 단위는 재수정하지 않고 근거와 함께 종료한다. 다른 단위를 자동으로 대신 선택하지 않는다.

카드 필수 항목:

```text
단위 ID / 목적 1개:
현재 기준 HEAD 또는 파일 해시:
구형 제공 위치·심볼·줄 범위:
현재 재사용 위치·호출자·설정 소비자:
그대로 보존할 입력·출력·부작용 계약:
허용 파일·심볼·설정 키:
금지 변경·허용하지 않은 후속 기능:
실패 재현과 최소 회귀 사례:
성공 판정·사용자 확인 방법:
중단 조건·해당 diff만 되돌리는 방법:
상태 / 실행 명령·종료 코드 / 미확인 항목:
```

필요한 공개 인터페이스 변경이나 새 의존성이 발견되면 카드에 이유·대안을 남기고 **그 단위만 보류**한다. 전체 프로젝트를 재설계하거나 관련 없는 모든 일을 중단할 근거로 삼지 않는다.

| Self-Ask | 필요할 때만 제한된 하위질문과 중복 제거 | 매 질문의 강제 3개 호출·검색 OFF 무시 | `service/rag/SelfAskPlanner` |
| 진단 표 | 단계별 입력·출력 건수, 생략 이유, 원인 근거 | 무정제 HTML·inline 실행·전체 프롬프트 공개 | `TraceHtmlBuilder`, `chat-trace-ui.js` |
| DebugCopilot·기여도 | 실제 저장된 이벤트를 근거로 한 원인 후보·안전한 설명 | 휴리스틱을 실제 원인 확률로 표시, 명령 자동 실행 | `DebugCopilotService`, 현재 attribution 렌더러 |
| 벡터 로그 | 격리·차원 불일치·검색 제외 이유의 관측 | 구형 벡터·캐시·학습 JSONL·로그를 지식으로 통째로 적재 | `VectorMetaKeys`, `VectorStoreService`, 기존 격리 서비스 |
| 진단 보존 규칙 | 생성→정제→전송→표시 계약을 회귀 테스트로 보호 | 모든 클래스 영구 불가침, 클래스 개수만 검사 | 기존 프로젝트 지침에 짧은 범위 제한 삽입 |

위 파일 중 8개 핵심 파일은 현재·구형에 모두 있고 내용이 다르다. 전체 덮어쓰기는 현재 개선을 잃을 위험이 있다. 구형에 있다는 이유만으로 '정상 동작'이라고 부르지 않는다. [C01, D01–D02]

## 7. API를 메인 답변에 사용하는 변경 계약

### 7.1 정확한 목표

API 모델을 보조 평가·실패 후 대체에만 쓰지 않고 **사용자가 기본 대화의 답변 생성 모델로 직접 선택**할 수 있게 한다. 자동 배정 후보 확대는 별도 단위다. 로컬 선택지는 유지하고, API를 켜기 위해 `llm.provider`와 모든 로컬 endpoint를 전역 교체하지 않는다.

기존 연결:

```text
GET /api/chat/models
→ chat-model-picker.js / 기존 modelSelect
→ 기존 요청 model + strictModelSelection
→ ChatWorkflow의 선택 검증
→ DynamicChatModelFactory의 기존 호출
→ LlmRouterAspect의 등록 경로 해석
→ 기존 provider client / 기존 프롬프트
→ 기존 답변·출처·스트림·저장·트레이스
```

`LmsApplication`, 기존 AutoConfiguration.imports, `NovaOrchestrationAutoConfiguration`에 등록 근거가 있다. 실제 프록시 적용은 통합 테스트로 검증한다. [S22–S24]

### 7.2 사용자 선택 의미를 보존

| 선택 | 유지할 동작 |
|---|---|
| 직접 선택 `strictModelSelection=true` | 정확히 고른 등록 경로로 생성. 실패하면 원인을 반환. 몰래 다른 공급자·로컬로 바꾸지 않는다. |
| 기존 선호 선택 | 현재 허용된 대체 정책만 적용하고 요청 모델·실사용 경로·이유를 구분한다. |
| 기존 자동 선택 | 승인된 후보와 기존 예산 안에서만 선택한다. API 자동 후보 추가는 API-03에서 별도 확인한다. |

라우트 내부 ID `llmrouter.api3`와 실제 provider model ID를 구분한다. 브라우저에는 서버가 인정한 경로 ID만 입력받는다. 임의 URL·API key·권한 범위를 요청으로 받아 라우터에 주입하지 않는다. provider 키는 기존 `KeyResolver` 및 credential 해석 경로를 사용한다.

**직접 API를 선택할 수 있게 하는 것과 모든 보조 LLM 호출을 그 API로 바꾸는 것은 다르다.** Self-Ask·판정·제목·Display 힌트 등 다른 역할의 모델·예산은 이 작업에서 바꾸지 않는다. 기본 모델 저장과 세션별 선택도 구분한다. 현재 `CurrentModel(1L)`을 세션 저장소처럼 사용하지 않는다. [S11]

### 7.3 사용할 수 있는 공급자와 호출 규격

현재 등록된 `api3`, OpenAI 계열, `gemini-pro`, `mistral-medium`, `external`을 후보로 조사하되, 실제 키·경로·지원 규격이 확인된 **한 개**만 첫 단위에 선택한다. 현재 설정에 있는 모델명이 오늘도 사용 가능하다는 보장은 없다. 계정별 허용 모델·해당 provider의 공식 문서와 기존 메타데이터 조회를 기준으로 확인한다.

LangChain4j 1.0.1의 `OpenAiChatModel`은 Chat Completions 경로다. Groq·Gemini의 호환 endpoint가 공식 문서에 있지만 지원 옵션이 모두 동일한 것은 아니다. 따라서 manifest의 `responses`, `anthropic_messages`, `evaluate`를 URL만 바꿔 Chat Completions로 취급하지 않는다. [W1–W3, W5]

현재 구현에 해당 규격의 검증된 adapter가 있으면 그것을 사용한다. 없으면 그 모델을 선택 불가로 표시하고 이유를 보여준다. 이번 범위를 넘어 새 SDK·새 파이프라인·일괄 라이브러리 업데이트로 해결하지 않는다.

Jev는 판단·라우팅용으로 유지한다. 기존 판정 후보를 넘어 모델 설정·예산·권한을 바꾸게 하지 않는다. 일반 문장 답변을 만드는 API는 별도의 현재 등록 경로에서 선택한다. [S21, W4]

### 7.4 API-01 — 한 API 경로를 메인 대화에서 직접 선택

**목적:** 현재 준비된 단일 API 경로를 기존 UI에서 고르면 해당 경로가 일반 답변을 생성한다.

**우선 조사 후보:** `llmrouter.api3`. 이것은 구형을 복사할 대상이 아니라 현재 존재하는 보조 경로다. Groq 계정 가드가 충족되지 않으면 준비 완료로 만들지 않는다. 사용자가 이미 허용한 다른 기존 API가 준비돼 있으면 카드에서 그 한 경로를 명시한다. 자동으로 유료 공급자로 바꾸지 않는다.

**초기 변경 후보:** `main/resources/application.properties`의 기존 선택 허용 키, 실제 활성 설정의 해당 `llmrouter.models.<key>` 항목, `configs/cloud-models.manifest.yaml`의 해당 한 행. 실행 전에 실제 origin을 확인한다. 같은 키를 다른 설정 파일에 또 추가해 우선순위 문제를 만들지 않는다.

**읽어서 검증할 경로:** `ChatModelCatalogService`, `CloudModelRouteClassifier`, `HybridLlmGatewayProbeService`, `ChatWorkflow`, `DynamicChatModelFactory`, `LlmRouterAspect`, `chat-model-picker.js`. 설정으로 해결되면 Java/JS를 수정하지 않는다. 내부 로직 수정이 필요하면 해당 심볼 하나의 결함을 카드에 고정하고 나머지 동작은 보존한다.

**최소 작업:**

- 실제 원격 선택 허용값과 origin을 확인한다. 이 작업의 승인된 배포 범위에서만 기존 키를 활성화한다. 키 존재만으로 사용자 허용을 추정하지 않는다.
- 해당 경로와 manifest의 모델·provider·endpoint·enabled를 맞춘다. 공식 근거 없는 후보나 전체 manifest를 일괄 활성화하지 않는다.
- 공통 원격 선택 허용값을 켜기 전후의 전체 카탈로그를 비교한다. 새로 선택 가능해지는 경로가 승인한 한 개와 기존 승인 범위를 넘으면 채택하지 않는다. 관계없는 기존 경로를 임의 비활성화해 맞추지도 않는다. 현재 설정/필터로 이 범위를 지킬 수 없다면 해당 변경만 보류한다.
- 카탈로그 판단은 생성 호출을 하지 않는다. 키 누락·계정 증명 누락·호출 규격 미지원·일시 장애를 구분한다.
- 직접 선택은 `fallback-only=true`여도 가능한 현재 계약을 보존한다. `weight`·전역 자동 선택 후보를 바꾸지 않는다.
- 일반 답변은 기존 메인 호출을 사용한다. `apiAttempt()`의 cue JSON과 1024 출력 상한을 일반 대화로 가져오지 않는다.
- AOP가 해석하지 못한 `llmrouter.*`를 factory가 차단하는 예외는 유지한다. 정상 프록시를 실제로 통과하는 테스트를 작성한다.

**검증:** 아래는 제안 테스트명이며 기존 동등 테스트가 있으면 확장한다.

- `RegisteredApiMainSelectionContractTest`: 카탈로그의 경로 ID가 실제 메인 요청의 provider/endpoint/model로 이어진다. 보조 판정 호출로 끝나지 않는다.
- `RemoteSelectionAdmissionTest`: 허용 false, route disabled, manifest disabled, key missing, protocol unsupported에서 미승인 외부 호출은 0회다. 공통 허용값 변경 전후의 selectable 경로 집합도 비교해 미승인 후보 노출이 없는지 확인한다.
- `StrictApiSelectionNoFallbackTest`: 선택한 API의 실패를 올바르게 보여주며 Ollama/다른 provider로 몰래 가지 않는다.
- `MainApiPromptParityTest`: 동일 fixture의 최근 대화·허용 기억·검색 출처가 현재 PromptBuilder/메시지 조립 경로로 전달된다. 응답 문자열의 완전 일치가 아니라 구조·근거 ID·예산·호출 횟수를 비교한다.
- 기존 sync·SSE·취소·실행 식별자 검사를 사용해 답변·기억 저장이 중복되지 않는지 확인한다.

**사용자 확인:** API 하나 선택→일반 질문→후속 질문→실사용 모델·진단 확인. 실제 API 호출은 테스트 계정·비용 한도·1회 시도 범위를 정한 뒤 수행하며, mock 통과를 실제 API 성공이라고 보고하지 않는다.

**완료 후:** `사용자확인대기`로 종료. API-02나 트레이스 작업을 연달아 하지 않는다.

### 7.5 API-02 — 저장·재접속에서도 선택 ID와 허용 판단 보존

**목적:** 이미 검증한 한 API 경로를 설정 저장·세션 재개·새로고침에서 잃지 않는다.

**타점:** `ModelSettingsService.changeCurrentModel`, `PageController`의 현재 모델 검증, `OpenAiModelSelectionPolicy`의 해당 호출부, 기존 설정 병합·세션 복원 소비자.

카탈로그에서 허용된 등록 route를 OpenAI 전용 문자열 목록으로 다시 거부하거나 로컬로 바꾸는 경우만 수정한다. endpoint/DTO를 새로 만들지 말고 기존 서버 카탈로그의 `resolve`·`selectable` 결과를 해당 호출부에서 재사용한다. 전역 기본값 변경 권한과 사용자의 현재 요청 선택은 계속 분리한다. 사용 불가한 저장 선택은 상태·이유를 보여주고 다른 모델로 조용히 바꾸지 않는다.

회귀: 로컬 선택 보존, Groq만 설정되고 OpenAI 키가 없는 경우, OpenAI 키는 있지만 원격 허용이 꺼진 경우, route 삭제/비활성, 세션 전환·뒤늦은 목록 응답, 저장 실패 후 입력 보존. 공개 API 응답 형태와 기존 ID는 바꾸지 않는다.

### 7.6 API-03 — 선택한 API 하나만 자동 메인 후보로 허용

**목적:** 자동 배정에서도 승인한 단일 API가 메인 생성 후보가 될 수 있다. API-01의 직접 선택 완료와는 별개다.

첫 대상은 API-01에서 검증한 바로 그 경로다. `api3`라면 기존 `LLMROUTER_API3_FALLBACK_ONLY`와 `llmrouter.models.api3.weight` 등 실제 소비되는 설정만 대상으로 삼는다. 새 전역 라우터를 만들지 않는다. `stage=chat`은 현재 코드에서 힌트일 수 있으므로, 선언만으로 보조 역할과 격리됐다고 주장하지 않는다.

변경 전에 `llmrouter.auto`의 모든 관련 호출자를 확인한다. 전역 fallback-only·weight 변경이 Self-Ask/판정/배치/Display 등 의도하지 않은 역할에 API 호출을 늘리면 그 변경은 채택하지 않는다. 현재의 서버 검증된 요청/역할 컨텍스트를 소비하는 후보 필터 안에서만 메인 요청의 허용 범위를 좁힌다. 해당 구분을 기존 내부 계약으로 표현할 수 없으면 API-03만 보류하고 인터페이스 확장안을 별도 제시한다.

회귀: 직접 선택 우선, 비허용 provider 호출 0, 보조 역할의 기존 호출 수 유지, API 인증 실패·429·quota·timeout·취소별 이유 보존, 비용 예약의 중복 없음, 불명확한 실행의 무조건 재생성 없음. 사용자가 설정한 예산보다 넓은 계정 한도가 있다는 이유로 제한을 풀지 않는다.

## 8. 트레이스·쿼리 이식 단위

각 단위는 후보 목록이며 한 번의 작업 권한이 아니다. 이전 WP에서 이미 해결된 부분은 현재 실패 테스트가 재현되지 않으면 건너뛴다.

| ID | 작은 목적 | 기본 수정 경계 | 반드시 확인할 반례 |
|---|---|---|---|
| TRACE-01 | 지정한 안전 숫자·불리언의 타입을 끝까지 보존 | `SafeRedactor`의 정확한 키/타입 처리와 해당 projection 호출부 | 같은 이름의 비밀 문자열, 중첩 미정제 map, 반복 정제로 타입 손실 |
| TRACE-02 | 중첩 표 행 제한이 다른 진단 그룹을 지우지 않음 | `chat-trace-ui.js`의 해당 행 제한 함수 | 120행 내부 표 뒤 terminal 그룹, 머리글·정렬·생략 수, DOMPurify 유지 |
| TRACE-03 | 현재 생산되는 진단 그룹 하나를 화면에 연결 | `TraceHtmlBuilder`의 선택된 그룹과 현재 생산자 | 펼치기 때문에 모델·검색·기억 저장이 추가 실행됨 |
| QUERY-01 | 구형의 작은 질의 변환 동작 하나를 복원 | `QueryTransformer` 또는 키워드/별칭 서비스 중 하나의 심볼 | 짧은 후속 질문, 고유명사·부정어·수치 변경, 검색 OFF인데 확장 호출 |
| TRACE-04 | 같은 답변의 캡처/누락 상태를 유지 | 기존 pointer·snapshot의 해당 연결부 | 다른 답변/owner로 연결, latest 전역 대체, 취소 뒤 잘못된 저장 |
| TRACE-05 | 저장 범위 내 동일 요청 로그 조회 개선 | 기존 `DebugEventStore` 조회 및 해당 관리자 소비자 | 최신 N개 밖 이벤트 누락, 권한 불일치, 필터 전에 잘라내기 |
| TRACE-06 | 기존 재접속 계약 내 중복·누락 표시 보강 | SSE 커서·조회·UI의 승인된 좁은 경계 | timestamp 역전, ring eviction, 오래된 cursor, worker 누수 |

TRACE-01/02는 이전 보고의 격리 재현을 출발점으로 하되 이번 실제 저장소에서 다시 확인한다. 이전 재현 수치를 새로운 빌드의 결과로 복사하지 않는다.

TRACE-03의 첫 그룹은 `qtx.*` 또는 `keywordSelection.*` 중 현재 생성·소비가 확인된 하나만 택한다. 질의 디버깅은 `queryId`, 파생 관계, 선택 이유, 해시·길이, 후보·채택·제외 건수, 근거 이벤트 연결을 우선한다. 대화 원문·프롬프트·비밀 문자열을 일반 로그나 공개 화면에 넣지 않는다. 디버깅 표시를 복구하는 작업에 질의 알고리즘 변경을 섞지 않는다.

QUERY-01은 구형 함수의 장점이 입력 fixture에서 실제 확인된 경우에만 진행한다. 현재 원질의·후속 지시 대상을 유지하고, 새 재검색 루프나 무작위 변이·3개 모델 강제 실행을 추가하지 않는다. 변환 실패 시 같은 권한 범위 안에서 원래 질문을 유지하며 실패 사유를 별도 진단으로 남긴다.

TRACE-04 이후에 새 응답 필드·버전·HTTP 경로가 필요하면, 본래 인터페이스 보존 범위를 넘는 변경으로 카드에 적는다. 기존 인터페이스에 안전하게 수용되지 않으면 사용자 승인 전 구현하지 않는다.

### 이번 개정에서 자동 실행 대상에서 뺀 항목

이전 WP6의 새 snapshot repository·영속 저장 규격·새 bundle API, WP7의 일반 로그 appender·파일 reader 추가, OTel span 구조 변경은 **별도 승인 대기**다. 필요성을 없앤 것이 아니라 사용자가 요청한 단일 이식·인터페이스 보존에 맞춰 분리한 것이다. 기존 기능으로 가능한 표시·조회 복원부터 끝낸다.

## 9. 벡터 잔재를 재이식하지 않는 규칙

구형 데이터의 지저분함에 대한 사용자 관찰은 중요한 문제 제기다. 그러나 이번 ZIP 비교만으로 실제 운영 벡터 잔재의 종류·개수·삭제 대상은 확정되지 않는다. 신규 구조를 유지한다는 명분으로 벡터 DB를 초기화해서는 안 된다.

**VECTOR-00은 읽기 전용 조사**다. 기존 진단 기능으로 제한된 메타데이터만 확인한다. provider/index/namespace, 임베딩 식별자, 문서 유형·출처·검증 상태, 원본의 현재 유효 여부·수정/삭제 상태, 권한 스코프, 적재 주체를 연결한다. 코드 파일의 잔재와 실제 DB 레코드 잔재를 구분한다.

| 분류 | 처리 방향 |
|---|---|
| 현재 유효한 원본문서·허용된 기억 | 보존. 이번 이식의 회귀 기준으로 삼는다. |
| 구형 로그·TRACE·임시 합성 데이터 | 일반 사용자 지식으로 자동 승격하지 않는다. 현재 타입·scope 필터를 확인한다. |
| 출처/권한/원본 상태가 불명확한 항목 | 승인된 범위에서 격리 후보를 기록한다. 전역 조회나 임의 삭제로 해결하지 않는다. |
| 다른 임베딩 모델·fingerprint의 벡터 | 같은 차원이라는 이유만으로 섞지 않는다. 기존 차원/fingerprint 검사를 유지한다. |
| 삭제·수정된 원본을 가리키는 항목 | 기존 source revision·삭제 처리·재적재 차단 경로를 확인한다. 늦은 작업이 복원하지 못하게 한다. |

구형 벡터 데이터·캐시·학습 JSONL·전체 로그·가상 경험치 데이터·시크릿 파일은 이식 패키지에 넣지 않는다. 새 디버그 기록을 대화 기억이나 지식 벡터에 자동 적재하지 않는다. 진단 조회 실패를 vector upsert로 보상하지 않는다.

`VectorMetaKeys`, `VectorStoreService`, `VectorQuarantineDlqService`, `TrainRagIngestService`, `FinalizedMemoryPersistence`의 기존 계약을 먼저 쓴다. 최신 라이브러리 예제를 이유로 메타데이터 키나 저장 인터페이스를 교체하지 않는다.

VECTOR-01 같은 실제 수정은 **오염 유입 또는 검색 포함의 근본 원인 하나**가 확인됐을 때만 별도 카드로 만든다. `removeAll`, namespace 초기화, 전체 재임베딩, 공유 alias 교체는 이 지시서의 승인 범위 밖이다. API 답변 모델 선택을 바꿨다고 임베딩 모델도 바꾸지 않는다.

## 10. 판단 절차와 교차검증

실제 세 모델 호출을 의무화하지 않는다. GPT 프로가 한 문서에서 세 관점을 검토해도 된다. 결과에는 검증 가능한 요약만 남긴다.

**긍정 검토 프롬프트**

> 구형 로직의 재사용 이점 하나를 찾되 현재 같은 역할 구현부터 확인하라. 어떤 입력에서 무엇이 개선되는지, 바꾸지 않을 계약, 최소 통합 위치, 성공 테스트를 제시하라. 파일 존재·과거 완료 보고를 정상 실행 증거로 쓰지 마라.

**부정 검토 프롬프트**

> 제안한 한 이식이 현재 로직·세션·권한·예산·선택 모델·진단을 깨뜨릴 반례를 찾으라. 특히 구형의 과도한 게이트, 벡터 잔재, 숨은 외부 호출, 중복 서비스, 테스트 약화를 확인하라. 근거 없는 위험 나열로 모든 작업을 막지는 마라.

**중립 판정 프롬프트**

> 양쪽 주장보다 실제 소스·실패 재현·회귀 결과를 우선하라. 채택·폐기·보류 중 하나를 선택하고, 현재 구조를 유지하는 최소 diff인지 확인하라. 근거 부족이면 필요한 증거 한 가지를 구체화하라. 동의한 모델 수를 검증으로 취급하지 마라. 선택한 단위의 국소검증 후 사용자 확인을 기다려라.

| 가상 검증 상황 | 기대 결과 |
|---|---|
| 새 요구가 생겼는데 기존 trace 그룹을 '낡았다'며 삭제 | 해당 이식 밖 삭제를 거부하고 기존 계약 테스트를 유지 |
| API 선택 허용만 켰지만 manifest는 꺼져 있음 | 사유를 표시; 카탈로그 등록=호출 성공으로 오인하지 않음 |
| Groq 키는 있지만 계정 근거가 없거나 만료 | 준비 미확인 사유; 증명 조작·전역 spend guard 해제 없음 |
| OpenAI 키만 있고 명시적 원격 허용은 꺼짐 | 해당 경로를 사용자 허용으로 간주하지 않음 |
| API strict 선택 후 429/timeout | 원래 선택·실행 상태를 보존; 자동 로컬 변경·중복 생성 없음 |
| 자동 API 승격 때문에 제목/판정/배치에도 API 사용 증가 | API-03 실패; 메인 요청의 기존 스코프 안에서만 조정 |
| 디버그 열기 전/후를 비교 | route·검색 호출·생성 호출·기억 저장 횟수 변화 0 |
| 120행 표 뒤 오류/terminal 그룹 | 그룹이 살아 있고 생략 수가 정확함 |
| 새 질의 변환이 고유명사·'아니'·후속 대상을 바꿈 | 이식 채택 거부; 현재 동작 보존 |
| 검색 OFF·벡터 장애에서 인사/일반 대화 | 불필요한 외부 검색·강제 고품질 게이트로 전체 응답을 막지 않음 |
| 근거 검증 질문에서 검색 장애 | 검증한 척 답하지 않고 확인 범위·장애 사유를 분리 |
| 과거 로그 벡터가 사용자 지식으로 검색됨 | 기존 타입·scope 필터 원인만 수정 후보; 원본/인덱스 전체 삭제 없음 |
| 임베딩 차원만 같은 다른 모델 벡터 | 같은 공간으로 취급하지 않음 |
| 다른 사용자 snapshot ID로 관리자 URL 접근 | 기존 권한 정책 검사; ID만으로 허용되지 않음 |
| 다른 에이전트가 같은 대형 파일을 수정 | 재확인·범위 조정; 다른 diff를 덮어쓰지 않음 |
| 한 단위 테스트가 모두 통과 | 사용자확인대기로 멈춤; 다음 단위 자동 시작 없음 |

## 11. 검증 명령과 보고 계약

실행 담당은 실제 저장소에 있는 도구·sourceSet을 사용한다. 아래는 명령 형식이며 이 문서 작성 중 실행한 앱 테스트가 아니다.

```powershell
# 실제 Git 저장소에서 실행. 읽기 전용.
git rev-parse --show-toplevel
git status --short
git rev-parse HEAD
git diff --check

# 실제 Gradle wrapper가 확인된 위치에서 task 존재부터 확인.
.\gradlew.bat --version
.\gradlew.bat tasks --all
# 이후 실제 sourceSet의 검증 task에 현재 단위 테스트 FQCN을 지정한다.
# test 태스크가 해당 sourceSet을 실행하지 않으면 그 결과를 완료 증거로 쓰지 않는다.

# currentSourceRoot/main/resources 경로가 실제로 맞을 때만 실행.
node --check .\main\resources\static\js\chat-model-picker.js
node --check .\main\resources\static\js\chat-trace-ui.js
```

실패 테스트→최소 수정→해당 회귀를 기본으로 한다. 출발점에서 이미 통과하면 결함을 새로 만들지 말고 해당 단위를 이미 해결로 기록한다. 전체 build/test는 영향 범위에 맞게, 실행 코드의 채택·배포 전 단계에서 확인한다. 사소한 지시문 수정만으로 전체 clean build를 강제하지 않는다. 다른 작업의 GPU·포트·DB·실사용 세션을 테스트에 사용하지 않는다.

단위별 최종 보고:

```text
단위 ID / 상태:
바뀐 파일·심볼·설정 키:
보존한 계약 / 의도한 변화:
최소 diff:
실패 재현 명령·종료 코드:
수정 후 검사 명령·종료 코드:
실제 API/서버/브라우저 확인 여부:
기존 실패와 이번 회귀 구분:
남은 위험·근거 부족 및 필요한 다음 증거:
해당 단위만 되돌리는 방법:
사용자가 확인할 행동 1개:
다음 단위는 시작하지 않았음:
```

검증 단계는 정적 확인, 문법 검사, 단위 테스트, 통합 테스트, 전체 빌드, 서버 기동, 실제 API 생성, 사용자 확인을 따로 적는다. 비용·성능이 좋아졌다는 결론은 같은 조건의 계측이 있을 때만 적는다. 제한에 걸린 사건을 모두 timeout으로 바꾸지 않는다.

## 14. 이번 개정의 확인 수준과 종료

이번에 수행한 것: 입력 파일 해시 재확인, ZIP 목록 확인, 선택된 소스·설정·구형 문서 대조, 26개 근거 항목의 줄 범위 확인, 8개 핵심 파일의 현재/구형 제한 비교, 현재 JS 3개의 `node --check` 문법 검사. 상세 결과는 `INPUT_AND_VERIFICATION.json`에 있다.

이번에 수행하지 않은 것: 운영 소스 수정, 실제 사용자 Git 조회·변경, 전체 Gradle 빌드, Java 단위/통합 테스트, 브라우저 E2E, 서버 기동, 실제 API 모델 호출, 실 DB/벡터 잔재 검사. 이전 SafeRedactor·DOM·SSE 재현을 이번에 재실행한 것으로 쓰지 않았다.

권장 첫 실행: **현재 기준 확인 후 API-01 한 단위만**. 이미 맡겨진 활성 이식 단위가 있으면 새 단위로 덮지 말고 그 범위를 먼저 존중한다. TRACE-01/02가 더 시급하다고 판단돼도 임의로 바꾸지 않고 사용자에게 단위 선택을 맡긴다. 한 단위의 국소검증이 끝나면 후속 고도화 없이 종료한다.
