## 요약

노바 집중 답변은 페이지 번호와 다음/이전 페이지 조작 없이, 글자가 차례로 나타나고 화면이 차면 오래된 줄부터 위로 밀려 사라지도록 변경한다. 마지막 글자는 읽을 시간을 확보한 뒤 자동으로 숨긴다. 사라지는 것은 표시 내용이며 대화 기록과 기존 수음·전사는 유지한다.

이 보완 지시서는 이전 지시서의 9절, 10.1절, 10.2절 및 관련 검증 조건에서 충돌하는 표시·타이머 요구만 대체한다. 단일 대화방, 제한된 모델 문맥, 인증·소유권, 중복 제출 방지, 기존 호출어 감지 구조는 유지한다. 일반 Conversate 힌트의 페이지 기능과 기록 조회 API의 cursor pagination까지 삭제하지 않는다.

Meta 공식 웹앱 자료는 기존 웹 기술을 통한 렌즈 UI와 600×600 표시 영역을 안내한다. 따라서 기존 렌즈 웹앱의 표시 계층을 수정한다. 메타 시스템 전체의 호출어를 바꾸거나, 닫힌 앱을 임의의 음성으로 깨우는 기능으로 범위를 확대하지 않는다.

## do02 — 변경 블록

### A. 사용자에게 보일 흐름

사용자가 기존 Fold6 웹 전사를 켜고 노바 음성 호출을 ON으로 설정한다.

노바 감지 → 집중창 열기 → 현재 질문을 실시간 표시 → 확정 질문을 한 번 제출 → 답변 텍스트를 순차 표시 → 화면이 차면 한 줄씩 자동 이동 → 마지막 글자 표시 완료 → 마지막 내용 유지 → 천천히 숨김 → 후속 발화가 없으면 집중창 종료 및 일반 Conversate 복귀.

답변을 읽는 데 페이지 번호, 페이지 버튼, 반복적인 손동작이 필요하면 요구사항 미충족이다. 화면 전체를 주기적으로 지웠다가 다음 페이지를 띄우는 방식도 기본 동작으로 사용하지 않는다.

입력 전사는 인식 결과가 들어오는 즉시 기존 draft를 갱신한다. 음성을 다시 느리게 재생하거나 입력 전사에 불필요한 타자 지연을 추가하지 않는다. 천천히 보여줄 대상은 AI 답변이다.

### B. 생성 속도와 표시 속도 분리

기존 응답 생성·근거 검증 경로를 유지하고, 통과한 텍스트를 클라이언트 표시 큐에 넣는다. 서버의 모델 생성 속도나 네트워크 패킷 간격이 곧 글자 표시 속도가 되지 않도록 한다.

현재 Focus 경로가 완성 답변만 반환한다면, 먼저 그 답변을 받아 글자별로 순차 표시한다. 이것은 표시 효과이며 실제 생성 도중 스트리밍이 아니다. 첫 글자가 보이는 시점을 앞당긴다고 주장하지 않는다.

현재 코드에서 실제 부분 응답 전송이 이미 검증돼 있다면 그 경로를 활용할 수 있다. 그렇지 않으면 이번 표시 변경 때문에 ChatWorkflow 전체를 갈아엎거나 검증 이전 모델 토큰을 그대로 노출하지 않는다. 진짜 부분 응답을 연결할 때에는 부분 텍스트도 외부 출력에 허용된 것인지, 최종 교정과 불일치할 때 어떻게 처리하는지 별도로 검증한다.

전송은 기존 poll/relay의 답변 단위 또는 검증된 청크 단위로 한다. 글자 하나마다 HTTP 요청, DB 저장, LLM 호출을 만들지 않는다. 같은 답변 snapshot을 다시 받으면 새로 재생하지 않는다.

### C. 연속 표시기

신규 제안 파일: resources/static/assets/display/display-focus-flow.js

책임은 답변 수신, 표시 위치, 줄 이동, 표시 완료, 마지막 내용 숨김이다. 호출어 감지, ASR, RAG, 대화방 생성은 맡기지 않는다. 기존 UMD/CommonJS 테스트 구조와 충돌하지 않는 작은 모듈로 구현하고 Fold와 Meta에 재사용한다.

- 표시 단위는 사용자가 한 글자로 인식하는 단위인 grapheme이다. Intl.Segmenter의 granularity: grapheme 지원 여부를 검사한다. 한글 조합문자와 결합 이모지를 UTF-16 인덱스나 split('')로 자르지 않는다. 미지원 기기에서는 기존 검증된 분리기를 재사용하거나 문장 단위 표시로 안전하게 대체하고 제한을 보고한다.
- 이전에 공개한 접두부와 아직 표시하지 않은 후속 텍스트를 분리한다. 스트리밍 중 미완성 Unicode 경계는 다음 조각 또는 최종 완료까지 보류한다. 이미 표시한 글자 앞에 수신 조각을 잘못 끼워 넣지 않는다.
- 신규 글자를 현재 줄 끝에 추가하고, 줄바꿈 시 실측 높이에 맞춰 표시 영역을 유지한다. 화면이 차면 가장 오래된 완성 줄을 한 줄씩 위로 이동시킨 뒤 제거한다. 아직 출력 중인 마지막 줄은 제거하지 않는다.
- 오래된 줄의 제거는 가시 영역 정리일 뿐이다. 미표시 답변을 버리지 않고, 저장된 전체 답변도 변경하지 않는다. display-only 렌더링을 위해 뜻, 부정, 숫자, 단위, 인용 표시를 잘라내지 않는다.
- 한 줄마다 충분히 표시될 수 있게 순차 출력과 줄 이동을 직렬로 관리한다. 이동 애니메이션 중 새 이동을 중첩하지 않는다. 한 번에 전체 화면을 자동 교체하는 구현으로 바꾸지 않는다.
- 이미 표시한 줄과 현재 줄만 제한된 DOM으로 유지한다. 매 글자마다 전체 대화 기록 DOM, 전체 답변 측정, 신규 타이머 수백 개를 생성하지 않는다. 원문은 textContent 등 안전한 텍스트 경로로 넣는다.
- requestAnimationFrame의 timestamp/단조 시간 기준으로 누적 간격을 계산하고 예약 콜백은 하나만 유지한다. 글자 갱신이 없으면 DOM에 쓰지 않는다. 긴 중단 뒤 밀린 글자를 한 프레임에 모두 공개하지 않는다.
- visibilitychange로 숨겨지면 표시·이동·페이드 진행을 멈춘다. 복귀 시 서버의 현재 activation/turn 유효성을 확인하고, 유효하면 남은 위치에서 이어간다. 만료·닫힘·다른 답변으로 교체됐으면 이전 출력을 되살리지 않는다.
- 표시 큐는 기존 답변 길이 상한 내에서 유한하게 유지한다. 길이를 초과하거나 계약이 깨지면 표시 제한을 알리고 전체 기록 접근은 유지한다. 끝부분만 잘라 정상 완료로 보고하지 않는다.

### D. 설정

기존 노바 호출 ON/OFF는 그대로 둔다. 아래 항목은 새로운 focus.presentation 하위 설정의 제안이며, 기존 동명 설정이 있으면 먼저 통합한다. 값은 실험 시작값이지 Even의 실제 수치나 실기기 최적값이 아니다.

| 항목 | 신규 제안 이름 | 시작값·허용 범위 |
| --- | --- | --- |
| 글자 순차 출력 | sequentialTextEnabled | ON. OFF여도 페이지 버튼으로 되돌리지 않고 읽기 간격을 둔 완성 줄 단위 자동 표시를 제공한다. |
| 글자 간격 | charIntervalMs | 80ms, 50–160ms |
| 표시 줄 수 | maxVisibleLines | 6줄, 4–8줄. 실제 글꼴과 화면 높이를 넘지 않게 실측 제한한다. |
| 마지막 내용 자동 숨김 | autoFadeEnabled | ON |
| 마지막 내용 유지 | tailHoldMs | 5,000ms, 2,000–15,000ms |
| 사라지는 시간 | fadeMs | 400ms, 200–1,000ms |

문장 끝 추가 대기 200ms, 줄 이동 200ms는 초기 내부값으로 제안한다. 첫 구현에서 설정창을 불필요하게 늘리지 않는다. 읽기 불편을 줄이기 위해 Fold에 표시 일시정지/계속과 저장된 답변 다시 보기를 제공한다. 재표시는 새 LLM 호출이 아니다.

autoFadeEnabled=OFF는 활성 집중창 안에서 답변 본문의 자동 숨김을 끄는 의미다. 사용자의 닫기나 서버의 정상 집중 대화 종료까지 무효화하지 않는다. 순차 출력 ON/OFF 변경도 답변을 다시 생성하거나 대화방을 새로 만들지 않는다.

일반 힌트의 hintTtlMs, autoPageMs, hintPageLines 및 기존 발화 제출 설정을 이 설정으로 대체하지 않는다. 기존 followupIdleMs 값도 이번 표시 효과 때문에 임의로 변경하지 않는다.

### E. 마지막 글자와 자동 숨김

최소한 다음 세 사건을 분리한다.

| 사건 | 의미 | 후속 대기 시작 여부 |
| --- | --- | --- |
| 답변 생성 완료 | 서버가 최종 답변을 확보했다. | 시작하지 않는다. |
| 최초 글자 표시 | 렌더러가 첫 글자를 DOM에 반영했다. | 진단만 기록한다. |
| presentation_done | 최종 답변 수신 완료, 미표시 큐 비움, 마지막 줄 이동 완료, 마지막 글자 DOM 반영을 모두 만족했다. | 이때 한 번 시작한다. |

이전 지시서의 첫 render receipt → WAITING 즉시 전환은 대체한다. 서버는 답변 표시 중임을 알 수 있어야 하며, 기존 20초 대기로 출력 도중 집중창을 닫으면 안 된다. 마지막 표시 완료를 관측하는 주 대상은 Meta 렌즈이고, Fold 미리보기의 빠른 완료로 렌즈를 닫지 않는다. 표시 대상 선택과 연결 미확인 처리는 명시적으로 구분한다.

presentation_done 이후 마지막 본문은 tailHoldMs 동안 남기고 fadeMs 동안 천천히 숨긴다. 동시에 기존 followupIdleMs로 후속 질문을 기다린다. 예를 들어 마지막 글자 표시 시점을 T라고 할 때, 시작값에서는 T+5초부터 본문을 숨기기 시작하고 T+5.4초에 숨김을 끝낸다. followupIdleMs가 20초이면 T+20초까지 후속 발화가 없을 때 집중창을 닫는다. 본문이 사라지는 것과 대화가 종료되는 것은 별개다.

출력·줄 이동이 계속되거나 새 질문 draft가 있으면 본문 숨김 타이머가 먼저 실행되지 않게 한다. 답변 생성 실패·부분 스트림 중단은 정상 presentation_done이 아니다. 상태를 구분해 안내하고 기존 실패·취소 처리를 따른다.

표시 완료 확인은 현재 activationId/turnId/answerVersion과 주 표시 대상에 묶어 멱등 처리한다. 같은 poll, 첫 표시 확인, 늦은 이전 답변 확인, 중복 완료 확인으로 만료를 연장하지 않는다.

이전 제안의 POST /api/assist/display/focus/rendered와 receipt 전용 권한을 구현했다면, 최초 표시/표시 완료의 구분을 명시적으로 확장한다. 기존 일회용 첫 표시 ticket을 소모한 뒤 같은 ticket으로 완료까지 처리된다고 가정하지 않는다. 서버가 허용한 두 사건만 각 한 번 수용하도록 설계하고 만료·대상·소유권 검증을 유지한다. 읽기용 lens token을 방 생성·설정 변경·음성 입력 권한으로 승격하지 않는다. 이미 더 단순한 동등 계약이 있다면 재사용한다.

표시 완료 확인이 오지 않아도 서버가 무한히 대기하면 안 된다. 기존 출력 길이 상한, 지원 최저 표시 속도, 문장·줄 대기, 제한된 연결 여유를 반영한 유한한 표시 기한을 별도로 둔다. 최초 표시 미확인 grace와 긴 답변의 표시 소요시간을 혼동하지 않는다. 기한이 끝나면 표시 미확인/연결 문제로 종료하고 성공으로 기록하지 않는다. 숨겨진 채 만료한 화면을 복귀 직후 빠르게 재생해버리지 않는다.

마지막 글자 DOM 반영 확인은 렌더러의 처리 증거이지, 실제 렌즈 광학 출력이나 사용자가 읽었다는 증명이 아니다.

## de02 — 셋업 및 검증

### 1. 작업 순서와 실행 조건

현재 canonical root와 적용 지침, 실제 변경 대상, 다른 작성자의 중첩 변경을 먼저 확인한다. Git 초기화·브랜치·worktree 생성을 전제로 하지 않는다. 현재 운영 절차의 임대와 비밀 없는 파일 기준선이 허용하는 구간에만 최소 diff를 적용한다. 충돌 파일을 덮어쓰거나 타인의 변경을 되돌리지 않는다.

순수 표시기 회귀 테스트 → 실제 mountLens 연결 테스트 → 서버 표시 완료/타이머 테스트 → Fold 설정 연동 → 기존 힌트와 음성 회귀 → 실제 렌즈 순서로 진행한다. 테스트를 먼저 실패시키고 변경 후 통과시키며, 테스트의 입력과 완료 기준을 고정한다.

ZIP에서 이번 범위의 테스트 실행기와 Java 빌드 루트를 확인하지 않았으므로 실행 명령을 지어내지 않는다. 구현자는 현장에 존재하는 빌드/테스트 정의를 확인한 뒤 실제 실행 명령·범위·종료 코드를 de02에 적는다. 표시 효과 구현을 이유로 프레임워크, 모델, 전사 제공자, 새 애니메이션 라이브러리를 설치하지 않는다.

### 2. 필수 검증 시나리오

| 시험 | 통과 조건 |
| --- | --- |
| 일반 답변 | 한 글자씩 순서대로 표시되고 버튼 없이 끝까지 읽을 수 있다. 페이지 표시가 없다. |
| 600 grapheme 답변, 80ms/글자 | 문자 공개에만 약 48초가 필요하다. 20초 타이머로 조기 닫히지 않고 마지막 내용까지 표시한다. 문장·줄 대기는 별도다. |
| 한글 조합문자·결합 이모지 | 문자 중간 깨짐과 대체문자 출력이 없다. |
| 화면 초과 및 큰 글꼴 | 실제 높이를 넘지 않고 가장 오래된 완성 줄부터 사라진다. 미표시 내용 유실과 끝문장 절단이 없다. |
| 마지막 문장이 부정형·숫자/단위 포함 | 끝부분까지 표시하고 그 뒤부터 유지 시간을 계산한다. |

| 최초 표시와 완료 확인 | 최초 표시만으로 후속 대기를 시작하지 않는다. 완료 확인은 현재 답변에 한 번 적용된다. |
| 네트워크 지연/중단 | 빈 큐를 최종 완료로 오판하지 않는다. 정상 완료와 중단 상태가 구분된다. |
| 새 turn·close 뒤 늦은 callback | 이전 답변이나 fade callback이 새 화면을 수정하지 않는다. |
| 숨김·재표시 | 유효한 응답은 같은 위치에서 계속하고, 만료된 응답은 재생하지 않는다. 밀린 문자가 한 번에 쏟아지지 않는다. |

| 자동 숨김·후속 질문 | 마지막 글자 이후 설정만큼 남고 사라진다. 후속 대화 가능 구간과 본문 표시를 구분한다. |
| Focus 종료 | 기존 전사와 수음이 계속되고 같은 방에 전체 답변이 남는다. |
| 실제 주 렌즈 경로 | clientRole=test 성공만이 아니라 /lens/text → mountLens → 실제 Meta 표시까지 별도 확인한다. |

긍정 검토는 추가 생성 호출 없이 원하는 표시를 만들었는지 확인한다. 부정 검토는 긴 답변의 조기 만료, 글자 깨짐, 중복 재생, 미표시 내용 유실, 읽기 토큰 권한 확장을 점검한다. 중립 판정은 실제 테스트와 관측으로 남는 결과만 채택한다. 별도 에이전트나 새 채팅을 만들지 않는다.

### 3. 관측과 중단 조건

기존 진단 경로에 최초 문자 표시, 마지막 문자 표시, 표시 큐 잔량, 줄 이동 횟수, 페이드 시작/종료, 중복 억제 수, 실제 생성 호출 수를 필요한 범위에서 기록한다. 원문 답변·사적 전사·ticket·token·프롬프트는 새 로그에 남기지 않는다.

문자 유실, 반복 재생, 읽기 전 만료, 기존 수음 중단이 재현되면 새 표시 효과의 적용만 보류하고 해당 실패를 먼저 수정한다. 서버가 정상이라는 이유만으로 렌즈 동작 성공을 선언하지 않는다. 발열·전력 효과는 측정 전 개선으로 단정하지 않는다.

최종 제출물은 파일별 최소 diff, 실제 실행한 검증과 결과, 전체 답변 확보 후 순차 표시인지 실제 부분 응답 스트리밍인지의 구분, 실제 Meta 렌즈 확인 여부다. 실기기 미검증이면 그 항목을 남긴다.
