## 다음 작업에 적용할 절차

1. 상위 에이전트가 기준 SHA와 후보 SHA, 게시할 파일 경로, 파일별 담당자를 기록한다. Devin은 겹치지 않는 파일 집합을 검토하고 재현 명령과 결과를 반환한다. SOL 6.1 검수는 변경 범위와 의존성을 확인하는 역할, 게시 이력과 복구를 확인하는 역할로 나눈다. 집계에는 시작·종료·결과 회수·최종 채택을 각각 기록한다.
2. 복구할 코드와 테스트는 기능 단위의 커밋 SHA로 고정한다. 보관용 소스·설계 문서에는 접근 범위와 복원 검증을 연결한다. 키, 인증 상태, 세션 원문, 실행 로그와 재생성 가능한 산출물은 공개 Git에서 제외한다.
3. 최종 트리와 새로 공개되는 이력을 모두 확인한다. Git 2.31 이상에서 이력 검사 도구를 직접 실행할 수 있다. 신규 공개 경로만 비밀 패턴으로 검사했으면 그 결과는 해당 경로에만 적용한다. 전체 레거시 이력 판정에는 별도 검사가 필요하다.

```bash
git diff --name-status <public-base-sha> <candidate-sha>
python -B scripts/git_publish_review.py --candidate <candidate-sha> --base <public-base-sha> --json
python -B -m unittest scripts.test_git_publish_review
```

4. GitHub 게시 후 기준 SHA를 부모로 삼았는지, 변경 경로가 승인 목록과 일치하는지, 원격 파일의 바이트가 검증한 후보와 같은지 확인한다. 기록한 커밋 SHA로 필요한 파일을 다시 읽어 복구한다.

분류 수치는 공개 필요성을 가리는 출발점이다. 파일명으로 추린 항목에 실제 자격증명이 있는지와 과거 공개 이력 전체의 상태는 이 집계의 범위를 벗어난다.
