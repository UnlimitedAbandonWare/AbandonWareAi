## Source-edit lease lifecycle (begin → work → end, no leftovers)
- One lease = one cycle: `begin`/scope `claim` → edit with `verify` + `heartbeat` at progress boundaries → `end`/scope `done`. Release is mandatory on **every** exit path — goal complete/STOP (`$demo1-goal-complete-stop`), deferred/BLOCKED abandon (`abort`), idle/timeout, or session cancel — independent of commit success. "Later" is not allowed; wire release into the caller's finally/session-end path.
- Lifecycle observations (`agent_scope_lease.py who`, `lease_conflict_autoflow.py scan`): **live** = valid TTL or valid heartbeat or proven-alive owner; **stale** is an expiry observation, not proof of owner death or write authority; **orphan** = unreadable/corrupt lock. Expired unknown owners remain blocked on overlapping targets.
- A foreign **live** lease is never force-released, deleted, or stolen: proceed on non-overlapping targets, leave one `request-release` (agent channel, once per conflict fingerprint), report one `live lease: owner/topic/targets/ETA` line. Never ask the user to relay "please end your lease" to another session — user intermediation is reserved for a live lease that blocks urgent work long-term.
- Normal identified live contention stays **WAITING** across finite observation rounds. Continue independent targets; normal release permits a fresh acquisition attempt. A round timeout alone is not HOLD, completion or cancellation. Preserve WAITING conditions for the next authorized session if this session ends; no permanent scheduler is implied.
- Never use expiry-only reclaim for an unknown, remote or corrupt foreign owner. `reclaim` and automatic claim recovery preserve these reservations, including `--include-orphan` and preview. Proven same-host process death is rechecked by existing native recovery with fresh PID/start/host/root/leaseId/fingerprint/heartbeat/inventory evidence. Targeted reclaim passes `-RecoveryLockName` plus `-LeaseFingerprint`; other reservations remain untouched. A refreshed or invalid heartbeat stops movement, including refresh after receipt preparation.

## Parallel wait/resume contract (D1-PARALLEL-RESUME-GUARDRAILS-20261009-R1)

Independent targets and separated outputs may run in parallel; overlapping files (including different hunks and directory/child overlaps) have one writer lease. Target-set waiter order and a `free` observation are advisory.

Before waiting, preserve an immutable task/goal/plan revision, canonical root, exact target set, existence/type/path identity, full SHA256, relevant plan/invariants, and source/test/config/dependency inputs with current check results. Read failure is not absence. Never collect secrets, auth state or `.env` inputs, overwrite the original baseline, or reuse an old PASS after its bound inputs change.

After normal release, acquire a fresh own lease with a current manifest. Compare against the immutable baseline **after acquisition**, then reread/replan changed files and related calls/tests/config. Disjoint line changes are not semantic safety proof. Already-done work needs current source plus fresh checks before `SKIP_ALREADY_DONE` with zero writes. Deleted/renamed/recreated/newly-created/unreadable targets require explicit scoped path reevaluation; no automatic old-path recreation.

The fresh `source_edit_session.ps1 -Action begin -Json` receipt includes `leaseId`, `root`, `taskId`, lease fingerprint, manifest hash and declared write paths. `guarded_source_edit.js` checks root/task/generation and declared paths, then calls `verify -LeaseFingerprint <fresh> -RequireAbsentTargets` immediately before its edit tool. This switch rejects unexpected creation of a null-SHA target. Legacy post-edit verification retains its late-created behavior and is not a pre-edit resume gate. Heartbeat/end remain bound to the acquired fingerprint; an old generation must not renew or release a replacement.

`codex_auto_unblock.py lease-wait` accepts `--goal-revision`, `--plan-revision` and repeated `--input-path` for the declared non-secret source/test/config/dependency inputs. A live or queue wait creates `before.json`, target byte snapshots and exclusive `before.sha256` once. Its task/root/target/context must match on later rounds, and the original hash remains pinned across polls; read failure or changed baseline blocks that lane. Legacy baselines without this integrity record must be reevaluated rather than silently upgraded. No baseline is created for help, preview or an immediately free target.

Use the same explicit `--wait-id` for consecutive observation rounds of one task/context. Its exclusive waiter ticket is reused, so the next round does not queue behind its own previous ticket. `free` after a previous wait preserves and checks the original baseline, retires the own pending record as `READY_TO_ACQUIRE`, and still has `ownsTargets:false`. Cancellation retires only the matching own pending generation as `CANCELLED`; a failure to confirm either retirement returns `BLOCKED/pending-retirement-unconfirmed`, retaining the evidence that the old record may still be active. A changed task/context/wait generation cannot inherit the old ticket or baseline.

The lightweight observation fallback recognizes the native `awx.source_edit_session.lease.v1` record, which may omit `status`. A matching future native reservation remains live; directory reservations and an unscoped native reservation are not reported free. Malformed scope lists are blocking orphan observations. Neither a fallback result nor a waiter ticket grants ownership or authorizes reclaim; acquisition and any proven-dead recovery still use the native lease contract.

For a waited edit, pass `waited:true`, `task`, and `resume:{beforePath,beforeSha256,goalRevision,planRevision,decision}` to the existing `guardedSourceEdit` function. Missing baseline metadata invokes neither acquisition nor mutation. After its own fresh acquisition it consumes `lease_resume_check.py --gate`; then native strict verification and a second gate using the first `inputDigest` run before the edit tool. Plain `--before` comparison remains advisory: exit 0 means all unchanged, 10 means any content change (including disjoint), 20 means deleted/renamed/recreated/newly-created path, and 30 means unknown evidence. Path changes require scoped reevaluation and a new baseline/current manifest; no old Add File plan is recreated automatically.

The gate decision binds `action`, `goalRevision`, current integer contract `planRevision`, `inputDigest`, proposed `patchSha256`, all `rereadPaths`, `plannedAtUtc`, repo-relative `verificationOutput`, and the existing recorder's `contractBinding` as `verificationBinding`. It reuses `run_verified_command.validate_bound_receipt`: task/revision/contract/stage/command, actual argv, root, fresh JUnit cases, timestamps, source/test hashes and file identity must agree. Include related configuration/dependency files in the contract's declared `sourceFiles`; a bare exit 0 or zero-test/unbound report does not qualify. `APPLY` requires current RED evidence of the goal defect; `SKIP_ALREADY_DONE` requires current GREEN and invokes the edit tool zero times. Any content change requires a new plan revision, reread and fresh bound check. The wrapper transports receipt/decision JSON through UTF-8 base64 flags to preserve native Windows argv; this encoding grants no authority and is not encryption.

There is no atomic transaction between the last verify subprocess and the edit tool. Noncooperative mutation after that gate remains a limitation; do not claim all parallel writers are safe. Unknown identity/authority/path or malformed evidence is lane-local BLOCKED/HOLD. Shared build/cache/port/log contention is coordinated only on the affected resource through existing lane/quota/coop verification; DEFERRED is not PASS. No new global lock, daemon or bypass service.

Implementation evidence must distinguish this opted-in executable resume gate from advisory `resumeChecks` / plain snapshot comparisons or callers that do not declare a waited operation. A before.json or read-only drift report alone never grants write authority or proves automatic resume. The agent still authors the reread/replan decision; locally authored artifacts are cooperative evidence, not authenticated proof. Pending caller integration and acceptance scenarios must be recorded separately from the verified guarded edit path.
