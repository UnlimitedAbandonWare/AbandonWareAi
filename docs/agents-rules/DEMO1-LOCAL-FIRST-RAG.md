## Local-First RAG Repair Overlay
- Before source work, verify Java 17. Missing optional historical ZIPs, reports, or handoffs do not block live-checkout facts; named attachments, PatchDrop artifacts, AutoLearn intake files, and required acceptance evidence remain mandatory.
- Source mutation requires the existing owner, lease, immediate preimage and applicable PatchDrop checks defined above; a triad verdict is required only when that review is selected; `sessionId` and `ctx.memory` stay read-only unless user and active memory policy authorize mutation.
- Trace RAG defects UI -> controller -> workflow -> `PromptBuilder` -> retrieval -> provider -> stream/response -> persistence/restore; stop at the first source-backed broken seam. Never silently substitute providers or invent results; delivery (HTTP 200, UI/terminal output, hashes) proves neither semantics nor provider/wire attempts. Manage or stop only task-started processes and the task's BAT-managed target servers (DEMO1-SERVER-LIFECYCLE-VERIFY); report unrelated owners.

### Adopted RAG/BM25 configuration and safe recovery
- Preserve an explicitly user-adopted configuration within its recorded scope. Do not revert it solely because an older default, disabled feature template, or historical handoff differs. Temporary verification overrides return to the recorded pre-test baseline; they do not redefine the adopted configuration.
- This rule does not enable a feature or grant execution authority. A draft, screenshot, third-party suggestion, or property declaration is not evidence of user adoption or an observed effective runtime value. Respect the current task's read-only, no-restart, no-index-write and credential boundaries.
- Distinguish search enablement, index availability, auto-indexing, main-chat wiring and runtime observation. `bm25.enabled` and `bm25.autoIndex` are different controls. Do not force either flag, a broad automation flag, or a legacy OFF default without the actual consumer/configuration contract and the user's authorized goal.
- BM25 adoption requires a validated common corpus/chunk identity, the same applicable owner/visibility filters, main retrieval wiring and a relevant quality comparison. Until those exist, do not force main-chat BM25 ON or build new indexes, daemons or startup jobs.
- If an indexing workflow is separately adopted, use the existing configuration SSOT and a declared manual trigger or one change-detected job. Require duplicate prevention, task ownership, bounded execution, retention of the last healthy index on failure, and a health check before switching readers. Do not reindex at every runner start. The current CREATE-mode rebuild does not establish these guarantees.
- Preserve evidence-based recovery for a failed task-owned change or an explicit user rollback request. Verify the baseline and ownership, record the reason and proof, restore only eligible task-owned state, and stop on foreign drift. Never turn configuration preservation into a blanket rollback ban or a waiver of secret, ownership or Pinecone safety rules.
- Current BM25/sparse facts: `docs/RAG_SPARSE_STATUS.md`; verify with `python -B scripts/retrieval_facts_guard.py` before changing BM25 rules or flags.
