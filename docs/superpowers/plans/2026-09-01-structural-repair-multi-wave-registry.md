> **For Codex:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. The repository's source-edit preflight, ownership, lease, no-staging, and evidence rules take precedence over generic commit guidance.

**Goal:** Replace the single hard-coded structural-repair closure wave with a code-pinned, deterministic multi-wave registry; preserve wave 1 byte-for-byte; freeze an isolated wave 2 from a Stage-A predecessor bundle; and close only the `FallbackAwareChatModel` root-cause group through a focused RED/GREEN cycle and verified terminal event.

**Architecture:** `dynamic_rag_quant_audit.py` owns a canonical registry parser, a descriptor-parameterized wave loader, and a deterministic cross-wave aggregator. The public audit and metrics move to v2 identities while existing row, intake, proof, progress, and event schemas remain v1. Phase A migrates wave 1 without semantic drift; Phase B freezes the four currently open non-wave-1 groups into a second immutable intake; only then may the guarded Java repair run.

**Tech Stack:** Python 3 standard library and `unittest`; Java 17; Gradle Kotlin DSL; JUnit 5; PowerShell; repository-native structural audit, source-health, source-edit lease, and Superpowers preflight contracts.

**Approved design:** `docs/superpowers/specs/2026-09-01-structural-repair-multi-wave-registry-design.md` at approved/corrected SHA-256 `b2346ef213d06ee9a7433f95358a1c67dee9018425b8a291e8009c4aa7c85b01`.
