# Prompt Caching Guide (Codex / dot)

## 목적
공급자 프롬프트 캐시가 히트하려면 프롬프트의 **앞부분이 바이트 단위로 동일**해야 한다.
demo-1의 규칙 본문은 길고 안정적이고, 사용자 입력·컨텍스트는 매 요청 바뀐다.
둘을 섞으면 캐시가 깨지고 매 요청 전체 비용이 든다.

## 정적 블록 (캐시 대상 — 프롬프트 앞쪽, 변경 금지)
- `AGENTS.md` 전문 (현재 ~27KB, 상세는 `docs/agents-rules/`로 분할)
- `.windsurf/rules/*.md` 자동 로드 규칙
- 활성화된 스킬의 SKILL.md 본문
- 이 블록 안의 어떤 편집도 캐시 전체를 무효화한다 — 편집은 반드시 끝에 가깝게.

## 동적 블록 (캐시 비대상 — 프롬프트 뒤쪽)
- 사용자 요청 원문, 첨부 파일 인용
- 세션 상태(state.md), 저널/리스 스냅샷, 작업 중간 산출물
- 도구 결과·진단 출력 (생성될 때마다 다름)

## 규칙
1. 정적/동적 경계를 명확히: 시스템 규칙 → 도구 정의 → (세션 메모리) → 사용자 입력 순서를 유지.
2. 정적 블록에 회차별 값(타임스탬프, 세션 id, 임의 순번)을 넣지 않는다.
3. 긴 참조 문서는 본문에 인라인하지 말고 경로만 두고 필요할 때 읽는다
   (output-budget: 요약만 컨텍스트에, 원문은 `var/` 파일로).
4. 세션 누적 토큰이 예산 80%(144k)에 도달하면 `codex_context_status.py status`가
   `earlyWarning` + `demo1-session-state-checkpoint` 권고를 낸다 — state.md를
   남기고 새 세션으로 이어간다 (세션 메모리는 동적 블록이라 캐시에 영향 없음).
5. 측정: `python -B scripts/codex_context_status.py footprint --defaults`
   (기본 룰 풋프린트 ~12.4k 토큰, 2026-10-04 실측).
