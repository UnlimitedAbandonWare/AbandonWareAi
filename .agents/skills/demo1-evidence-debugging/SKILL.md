# Demo1 Evidence Debugging

증상과 원래 의도를 현재 소스의 최소 수정·검증까지 연결한다. `systematic-debugging`의 원인 조사, `demo1-invisible-eye`의 조건·반증 분석, `demo1-debugging-with-two-tools`의 집중 주기를 하나의 사건 기록으로 결합한다.

## 진입과 역할

이 스킬은 **사건 기록과 단계 연결**을 소유한다. 세 원본 스킬 전체를 차례로 실행하거나 새 심사·lease·실행기를 만들지 않는다. 이미 적용 중인 스킬의 증거와 현재 소스 세션을 재사용한다. `AGENTS.md`와 더 가까운 규칙, 사용자 범위·승인·기한이 우선한다.

읽기·분석 요청은 분석 범위를 지킨다. 수정 요청은 기존 권한 안에서 최소 패치와 검증까지 이어간다. 원인이 이미 입증된 작은 수정은 기존 증거를 확인해 바로 수정 진입점으로 넘긴다. 기술 단서가 없는 경우 필요한 관찰 하나를 요청하고 추측을 사실로 채우지 않는다.

## 사건에서 검증까지

1. **의도를 고정한다.** 원래 증상, 같은 입력의 기대 동작, 재현 조건, 허용 범위, 보존할 계약, 완료 조건과 예산을 `DebugCasePacket`에 담는다. 로그 원문은 복사하지 않고 위치·허용된 요약·식별값을 사용한다.
2. **현재 경계를 확인한다.** 활성 sourceSet과 owner/call path, 소스·빌드 식별을 확인한다. 소스 존재 → 빌드 포함 → 호출·활성 조건 → 실행 → 인과를 구분한다. 현재 플래그와 초기화 당시 평가값·순서·재평가 여부는 별개다. 모든 단계에 신규 검사를 할당하지 않는다.
3. **후보와 실험을 분리한다.** 원인이 불명확하면 보통 2–4개 후보에 지지·충돌 증거, 예측, 반증 조건을 붙인다. 관측 오류와 강한 대안, 공존 가능한 원인을 보존한다. 활성 실험은 하나이며 결과는 모든 후보 행을 갱신한다.
4. **구별 검사 하나를 실행한다.** 현재 결정을 바꿀 수 있는 가장 이른 미확인 경계에서 고정 조건·변경 변수·관찰 단위·누락 가능성·제한 시간을 정한다. 기존 증거를 먼저 재사용한다. 가설들이 같은 결과를 예측하면 아직 구별되지 않은 것으로 남긴다.
5. **기존 수정 경계에 넘긴다.** 의미적 RED 또는 기존에 확인된 재현과 원인 증거를 묶는다. 애플리케이션 수정 직전에는 [기존 세 역할 심사](../demo1-source-edit-three-way-preflight/SKILL.md)와 현재 owner·대상 lease·preimage·검증·복원 절차를 따른다. 심사나 쓰기 권한은 가설의 지지도와 별개다. 하나의 원인에 필요한 최소 변경을 한다.
6. **같은 증상을 검증한다.** 원래 입력·기대 의미의 집중 검증 후 영향받은 회귀와 명시된 인수 조건을 확인한다. 실패를 관찰했을 때만 실패 경계를 갱신한다. 새 실패가 있으면 해당 증거로 진단을 다시 연다.

## 진단과 인수 검증의 구별

| 종류 | 역할과 종료 조건 |
|---|---|
| 진단 | 한 주기에 관찰 슬롯 하나와 집중 검증 슬롯 하나를 정해 가설을 구별한다. 판단을 바꾸지 않는 반복 검색은 멈춘다. |
| 인수 검증 | 명시된 완료 조건·영향 경계의 테스트, runtime, UI 또는 필요한 외부 증거를 수행한다. 진단 슬롯을 다 썼어도 의무는 남는다. |

**필수 검증을 시작하기 위해 새 실패를 가정하지 않는다.** 단위 테스트가 통과하고 UI 취소 검증이 남았다면 `acceptance=pending`이다. UI 실패는 아직 관찰되지 않았다. 도구 두 개 제한을 전체 작업의 검증 상한으로 사용하지 않는다.

## 예외·복구와 중단

재시도·중복 부작용·취소·timeout·빈 결과가 관련되면 [사건 계약의 예외·복구 표](references/case-contract.md#예외복구)를 적용한다. 기존 실패 의미와 총 시간 예산을 보존하고, catch-all 성공이나 근거 없는 공급자 대체로 증상을 감추지 않는다.

막힘은 실제 의존 작업에 한정한다. 관련 조건이 바뀌지 않은 동일 blocker를 재호출하지 않는다. 원래 기한과 시도 횟수는 재개해도 유지한다. 세 번의 수정 실패 또는 기존의 더 이른 중단 조건에서는 추측성 추가 수정을 멈추고 현재 증거·대안·다음 한 검사를 제시한다. 독립적인 안전한 작업은 계속한다.

## 기록과 도구

상세 조사나 에이전트 인계에는 [case-contract.md](references/case-contract.md)를 읽는다. 한 번 읽은 증거를 같은 ID로 재사용하며 빌드·관찰 경계·비활성 후보도 함께 넘긴다. 같은 로그의 복제나 검토자 수는 독립 증거 수가 아니다.

기본은 현재 Codex와 로컬 증거다. 런타임 관찰 슬롯은 `Debug-RAG.bat` / `Debug-Meta-Display.bat -Action status`(읽기전용)로 시작하고, 힌트 지연·누락은 `-Action tail -Pattern` 또는 `restart -Loggers`다. Fold/안경 재현 뒤에는 `python -B scripts/devin_task_orchestrate.py capture --role wear --invoke`로 적색 스냅샷을 `data/agent-handoff/display-debug/`에 남긴 다음 패치한다. `var\debug`만 보고 패치하지 않는다. Browser·Computer는 해당 UI/환경 증명에, AWX 도구는 검증된 해당 진단에, 외부 연구는 불확실한 외부 사실에 필요한 경우만 선택한다. 공급자·DB·배포 권한을 확대하지 않는다. 외부 도구의 불가 상태는 독립적인 로컬 수리의 중단 사유가 아니다.

원문 private payload·credential은 출력·인계하지 않는다. allowlist된 count/hash/timing/boolean/reason과 참조를 사용한다. 사건 기록은 작업 맥락이나 기존 승인된 세션 보고서에 두며, 개인·애플리케이션 메모리의 영구 쓰기는 별도 명시 요청과 정책을 따른다.

## 결과

`확인된 원인과 범위 → 변경한 경계 → 실제 검증 → 남은 증거와 다음 조치 → 복원 정보` 순서로 보고한다. 소스 존재, 모델 설명, HTTP 응답, ACK, 해시, 단위 테스트만으로 전체 의미·공급자·UI 성공을 선언하지 않는다. 필수 증거가 없으면 정확한 `evidence_needed`와 검증 행동 하나를 남긴다.

선정·충돌 조정 근거가 필요할 때만 [selection-and-cross-review.md](references/selection-and-cross-review.md)를 읽는다. 스킬을 변경·평가할 때만 [evaluation-cases.md](references/evaluation-cases.md)를 사용한다.
