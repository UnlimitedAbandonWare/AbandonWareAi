# Oldest-first retention review

Use for an explicitly requested backlog cleanup. A plugin tag, old timestamp,
filename, empty file, or successful subset does not authorize deletion. The
existing completion helper remains the only deletion mechanism for completed
standalone Markdown directives. This review does not enable a watcher, generic
recursive deletion, consolidated-program retirement, or source mutation.

## Inventory and order

Declare document roots and depth before scanning. Include relevant temporary
instruction/report locations, but exclude application source, runtime settings,
keys/credentials, production data, build caches, recovery payloads, immutable
receipts and sealed bundles from the deletion candidate set. Discover closer
instructions and preserve unknown owners, locks, reparse paths and hardlinks.

Order by a corroborated authored date when available; otherwise record a
filename date or mtime explicitly as an ordering hint, with path as tie-breaker.
Dates never establish completion. Record scope limits, read failures and items
not semantically reviewed. Do not report a lexical inventory as source review.
An unreadable/held oldest item gets one exact next verification action. When the
user explicitly authorizes permission repair, save readable ACL evidence and
repair only those declared document paths, recording native exits and post-read
results. Do not change permissions recursively or clear unknown locks. Continue
independent work when the operating system still denies the repair.

## Five classes and deletion eligibility

| Class | Required finding | Action |
| --- | --- | --- |
| 완료 / completed | Every requirement is verified against current source and its required acceptance evidence, with an authoritative bound final report. | Delete only a disposable standalone directive whose reference/recovery checks pass; otherwise retain with the exact reason. |
| 중복 / duplicate | Identify a retained canonical artifact and prove byte equality or an explicit requirement-by-requirement absorption map, including unique constraints and pending work. | Preserve unresolved work and incoming execution references. Similar titles, shared topics and equal empty bytes are insufficient. |
| 미반영 / unimplemented | A named required behavior is absent or contradicts the current active owner; identify a focused falsifier and the retained requirement. | Preserve. If repair is needed and authorized, process one selected directive through the existing source intake/preflight/lease/verification workflow, then reclassify. Do not patch merely to increase deletion counts. |
| 보류 / held | Required bytes, ownership, source/test/runtime evidence or a stable reference binding is missing, contradicted or changed. | Retain; record the operation-local HOLD fields and one next check. Missing evidence is not proof of an unimplemented feature. |
| 참조 필요 / reference-needed | The artifact has continuing specification, decision, operational, provenance, test, recovery, or unique experimental value. | Retain; inactivity and abandonment labels do not prove dispensability. |

Store `category`, `classificationLevel=triage|requirement-reviewed`,
`deleteEligible`, `reason`, and `nextAction` separately. A completed patch may
still have `deleteEligible=false`. A duplicate may preserve an incomplete idea.
Do not force nonzero counts in any class.

A prior `cleanupStateAtPublication=retained` or `deleteAuthorized=false` records
the earlier operation; it is not a permanent retention instruction. A later
explicit cleanup authorization may support a new deletion request after current
proof and reference checks. Preserve the earlier receipt unchanged. Conversely,
do not erase a real continuing-reference requirement merely because authorization
changed. A triage row's default `deleteEligible=false` is not final adjudication.

## Current historical reconciliation

The current Desktop verification owner may create a **new** report when an old
report is missing or its source hashes have drifted. Read the exact current
directive bytes and enumerate all requirements, amendments, conditional work,
and acceptance criteria. Map each to current active source or retained canonical
specification paths/lines and hashes. Use Git history only when currently
readable and relevant; a commit message or unchanged HEAD is not working-tree
proof. Record `sourceHistory=unverified` if authorship is unknown.

Execute the required focused tests on current bytes. Retain the actual command,
exit code, result counts, log hash and tested source hashes. Where a directive
requires final build/runtime/browser/provider/hardware proof, verify that surface
or retain the item. Optional live proof remains optional; do not promote it into
a new requirement. Explain conditional non-applicability from source evidence.
Recheck source/evidence hashes immediately before preparing the cleanup request.

Only a fully satisfied requirement ledger may produce
`sourcePatchCompletion=verified`, `desktopFinalProof=verified`,
`allRequiredWorkComplete=true` and `completionFlag=true` in the new report.
Record `verificationMode=current-historical-reconciliation`, current timestamp,
exact directive hash, current source postimages, acceptance log bindings, and
any prior reports used as locators. These fields attest to the stated current
verification scope; they never invent a historical patch or external success.
An analysis-only report needs no fabricated application-patch completion flags.

## Duplicate and absorbed material

Record the retained canonical path/hash, every requirement mapping, and incoming
references from active instructions, scripts, manifests and related documents.
Inspect each reference's meaning: executable pointer, live documentation link,
historical provenance or example. Hash equality alone does not preserve a unique
entry point. Migrate an active pointer only with existing authority and validate
its consumer; otherwise retain the duplicate. Preserve provenance records.

For completed duplicate directives belonging to the same completed task, bind
each exact disposable Markdown path/hash in `relatedMarkdown` under that task's
whole final report. Independent completed tasks need separate requests.
Do not use completion flags to delete an incomplete duplicate, unrelated report,
unique experiment, `.txt` instruction, or sealed bundle. These remain classified
and retained until their actual artifact owner supplies a suitable retirement
contract. Do not bypass completed-directive verification through a shell delete.

## Explicit retirement of historical artifacts

A historical run result, expired concurrency/queue snapshot, or rejected-attempt
report may have no unfinished source requirement. Under explicit backlog cleanup
authorization, its provenance can be retained as an exact SHA-256 `.bin` plus an
immutable path/reason/commit/reference ledger. Historical value alone does not
require keeping every original filename indefinitely. This is artifact retirement,
not a claim that every historical build or patch described in it succeeded.

Read its complete content; separate live requirements and operational references
from historical observations. Check current source/test boundaries and active
references across declared source, scripts, skills and document roots. Retain any
unique pending idea or live entry point, or move its full requirements into a
retained canonical document before retirement. A triage default or old permission
flag must not replace this current content-based decision.

Use an exact reviewed allowlist and dry-run. A task-local artifact retirement
runner may reuse the existing helper's pinned native handle implementation for
`.md`/`.txt` historical artifacts. Require protected-root exclusions, directory
and file identity checks, hardlink/reparse rejection, current byte hashes, a
durably flushed ledger and verified `.bin` before marking that same held file
handle for deletion. Record every outcome and perform affected regression checks.
Never infer a recursive cleanup scope, erase recovery receipts, modify operational
configuration/secrets/locks, or set source-completion flags for historical reports.

## Pre-delete evidence and debugging

Before deletion, durably retain one task-local ledger containing the exact
target path/hash, authored/order-date basis, category, requirement coverage,
source path/line/hash or verified commit evidence, acceptance command/results,
canonical replacement if any, incoming-reference assessment, reason, owner,
authorization and the exact bound cleanup-request path. No raw prompts, secrets
or provider bodies belong in the ledger.

Run the existing helper dry-run first, inspect each result, then apply only
validated requests. Preserve its plan, immutable completion receipts, `.bin`
recovery payloads and JSONL journal. A failed journal, changed target or failed
proof stops that operation. Never weaken path, identity, hash or ACL guards.

Report `scannedCount`, five category counts, `requirementReviewedCount`,
`eligibleCount`, `attemptedCount`, `deletedCount`, `alreadyAbsentCount`,
`retainedCount`, `heldCount` and `failedCount`. Count actual failed delete/I/O
attempts separately from precondition holds, and link per-item reason codes and
native helper results. Verify deleted paths are absent, retained files unchanged,
recovery hashes match and receipts remain readable. Successful deletion is not
whole-repository cleanup or source certification.

## Decision checks

1. Implemented source but required live test absent: held, no mark/delete.
2. Exact incomplete duplicate with a unique execution pointer: duplicate and
   retained until canonical requirement and pointer preservation are proven.
3. Old completion report with changed source: held until current reconciliation.
4. Old directive with no report: new current reconciliation may complete it only
   after all actual requirements/tests pass and its report is durably bound.
5. Abandoned experiment containing unique recovery data: reference-needed.
6. Unreadable oldest item: item-local hold; a newer independent fully verified
   disposable directive may proceed.
7. Permission repair explicitly authorized: save the available ACL first, repair
   only pinned documents, verify read access and continue; never clear Git locks.
8. Expired queue snapshot or past run output with no pending requirement and no
   active reference: exact native-handle retirement with verified `.bin` and
   provenance ledger is eligible under explicit authorization.
9. A multi-task document contains a completed selected repair and unfinished
   follow-ups: do not claim whole-document completion. Preserve the full original
   in a hash-verified readable archive plus `.bin`, transfer pending instructions
   into a retained canonical follow-up document, and record selected-work completion
   separately from `wholeDocumentComplete=false` before removing its queue entry.
