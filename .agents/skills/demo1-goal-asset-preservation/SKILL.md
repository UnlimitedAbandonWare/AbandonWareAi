# Goal Asset Preservation

Preserve the user's needed capabilities while achieving the requested objective.
Treat a numeric target as part of the goal, not permission to sacrifice other
needs. This is a decision aid, not a guarantee of harmless behavior.

## Scope and authority

Use for consequential goal tradeoffs, disposal, cleanup, cost reduction, and
metric optimization with collateral effects. Skip ordinary wording changes,
read-only explanations, and tasks with no material asset/capability tradeoff.
Default owner: current authorized agent; this skill produces decisions and
adds fields to the existing goal contract. It grants no new mutation authority.
Preserve explicit user tradeoffs and earlier authorization; do not repeatedly
ask approval for an already authorized action with established prerequisites.

Reuse existing goal intake, evidence, and execution gates. Do not create a
second review, score, or mandatory agent triad. If a repository companion of
this skill is already active, reuse its contract rather than run both copies.

## Decide before optimizing

1. State the outcome, deadline, and real benefit. Identify the capabilities
   that must remain available, their users, and the evidence for that need.
   Separate confirmed needs, user preferences, and unresolved assumptions;
   do not claim to know a person's hidden intention.
2. Trace each affected asset to its functions, dependencies, and activation
   conditions. Consider normal operation, next relevant season/cycle, and
   credible failure/recovery use. Inactivity is an observation, not proof of
   uselessness. Protect recovery paths, rights, shared interests, and unique
   information as well as physical goods. Bound the horizon; no infinite
   inventory or speculative preservation of every imaginable use.
3. Check each candidate's hard conditions BEFORE any goal score: authority,
   protected capability floors, unique/irrecoverable value, and adequate
   evidence of replacement or recovery. A violated condition excludes that
   candidate even for an enormous reward. Check the combined final state of
   multiple actions and their transition order; individual eligibility cannot
   be combined blindly. An unknown material condition
   yields NEED_EVIDENCE for that action; continue independent viable work.
4. Prefer options that meet the goal with less collateral loss. Include
   keeping the asset/no action for comparison, reversible trials when they
   cannot interrupt essential service, and verified surplus disposal. A
   cheaper replacement is not ready merely because it is listed online.
   Verify suitability, availability, handover timing, and full costs first.
5. Compare eligible options using the existing objective. For cash, separate
   realized proceeds from transaction costs and non-overlapping required
   replacement/recovery provision. Do not double-count a cost already paid
   and reserved. Do not invent replacement costs for genuinely surplus goods.
   Track material noncash losses separately; money cannot cancel a failed
   protected condition. Past purchase price alone is not a reason to retain.
6. Recheck relevant conditions immediately before consequential execution:
   ownership, dependency changes, substitute readiness, and budget. Accept
   current supplied facts within their stated scope; do not request the same
   evidence again without a material freshness or consistency reason. Use the
   existing action/owner gate, execute only the authorized scope, then verify
   BOTH the target and retained capabilities. A proposal or receipt alone
   does not prove preserved function. If no eligible action meets the goal,
   report the shortfall and the smallest decision-changing next fact.

## Bounded operation and failure handling

Default decision pass: at most 15 minutes, 4 candidate actions, 12 affected assets,
20 evidence rows, and 800 words of result; scale only when the task requires it.
Use at most 3 targeted read-only probes, each with a 30-second timeout unless an
existing task budget is stricter. These are ceilings, not work to exhaust.
At budget exhaustion, preserve unresolved consequential actions and report
one next proof; don't turn a local unknown into a global stop.

Fail closed for the particular asset action on protected-loss,
authority-unproven, substitute-unproven, evidence-conflict, changed-precondition,
or secret-risk. Fail soft for an unavailable optional research/calculation tool;
use available evidence and label uncertainty. Report net-goal-shortfall
separately from unsafe action. Do not disguise expected loss as zero loss.

Use asset IDs, counts, and redacted evidence pointers. Do not collect or emit
credential values, private medical details, raw sensitive queries, or full
logs. Scan generated artifacts for accidental secrets; report counts/reasons.

## Removal and falsification

Restore only this skill's backed-up files or remove the exact created skill
directory after checking its resolved path. Remove only its marked routing
block; retain other work. Actual asset rollback needs its own feasible plan.
This skill is wrong if it lets reward override essential capability, treats
seasonal nonuse as surplus, double-counts replacement, or blocks verified,
authorized surplus disposal without a material reason. A working instruction
file does not prove that a different Desktop session has loaded or used it.

## Repository integration

directory is not a Desktop dependency. Reuse the existing goal and source-owner
route. Application-source writes, public APIs, credentials, and runtime proof
retain the repository's existing authority. For hidden dependencies, reuse
the current demo1-invisible-eye evidence once. No second review is required.
Instructions loaded in Notebook prove only Notebook discovery; record actual
Desktop invocation separately before claiming Desktop execution.
