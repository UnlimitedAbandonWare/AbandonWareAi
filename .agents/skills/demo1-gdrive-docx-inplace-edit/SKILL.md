# demo1 Google Drive .docx 원본 제자리 편집

사용자 확정 규칙(R-a~R-g)의 절차 본문은 이 파일이 유일한 SSOT다. 다른 스킬에는
포인터만 두고 같은 규칙을 복붙하지 않는다.

## 0. 트리거 — 이 요청이면 이 스킬

- docs.google.com / Google Drive 링크 + 이력서·경력기술서·포트폴리오·`.docx` 편집 요청
- "파일이 너무 커서 변경사항을 Drive에 저장할 수 없음" 류의 저장 경고 언급
- "원본에서 고쳐줘", "'편집하기'로", "사본 말고" 류 표현
- 반대: 제품 소스(`main/`·`/chat`·Display 파일) 수정 요청은 이 스킬이 아니다

## 1. 시작 체크

- 동시 편집자는 정확히 1명 — dot·데빈·Codex 중 이 문서를 여는 세션이 하나뿐임을
  journal/lease로 확인한다.
- 문서를 '편집하기' 모드로 연다. 보기 전용이거나 로그인 벽이면 HOLD — 비밀번호·계정
  입력은 절대 금지이며 승인 대기로 전환해 기다리지도 않는다(보고로 종료).

## 2. 절대 금지 (R-a, R-c)

- 사본(Google 문서 형식 사본 포함) 만들기 금지 — 항상 원본 링크의 '편집하기'
- 새 빈 문서로 내용을 옮겨 편집 금지, Drive에서 파일 다운로드 금지
- 저장 경고를 근거로 작업을 멈추거나 사용자 승인을 기다리기 금지

## 3. 저장 판정 (R-b) — 판정 근거는 재열기뿐

1. 편집 적용 → 저장 상태 표시가 멈출 때까지 최소 60초 대기한다.
2. "저장할 수 없음" 류 경고가 떴는지는 별도 필드(`warnShown`)로만 기록한다 —
   용량 때문에 뜨는 버그성 경고이며, 떠도 실제로는 저장된다. 경고 자체는 실패 증거가 아니다.
3. 새 탭에서 같은 링크로 재열기 → Ctrl+F로 방금 넣은 표본 문장과 지운 이미지 위치를 확인.
4. 결과는 `PERSISTED`(전부 반영) / `LOST`(전부 미반영) / `PARTIAL`(일부 반영) 셋 중 하나.

## 4. 배치 크기

- 한 배치 = 이미지 ≤5개 또는 한 섹션. 수십 MB급 문서는 "없는 기능의 이미지·GIF
  삭제"부터 — 용량이 줄면 저장이 안정된다.
- `LOST`면 같은 내용을 더 작은 배치로 나눠 1회 재시도. 연속 3배치 `LOST`면 HOLD —
  그 경우에도 사본·빈 문서 우회는 금지.

## 5. 내용 판정표 (R-d)

문서가 말하는 기능명마다 이 저장소 소스(`main/`)를 `rg`로 확인한다:

| 판정 | 기준 | 동작 |
|---|---|---|
| EXISTS | 기능이 실재 | 유지 |
| SIMILAR | 비슷한 기능이 실재(이름 다름) | 삭제 말고 설명을 실제 동작·이름으로 교정 |
| ABSENT | 기능 자체가 없음 | 그 기능과 그 기능만 설명하는 이미지·GIF 삭제 |
| UNSURE | 확인 불가 | 삭제하지 말고 남김 |

- 수치·성능 숫자·경력 근거는 출처 없으면 삭제/교정. 회사 경력 수치는 사용자가
  근거 없음을 확인한 항목 — 삭제.
- 기술 스토리는 `configs/stack-fit.yaml`의 story(SSOT)와 어긋나지 않게 쓴다.
- 백업본 문서로 명시된 경우 대량 삭제 허용.

## 6. 콘셉트·보존 (R-e, R-f)

- 콘셉트: "혼자 깊게 파고들어 구현·검증까지 해내는 몰입형 개발자". 기본기 먼저,
  과한 오타쿠 표현 금지, "협업이 어렵다"류 자기평가 문장 금지.
- 보존: 개인정보, 경력 회사명·기간, 동작하는 코드 링크, 실제 기능을 보여주는
  이미지는 지우지 않는다.

## 7. 장시간 위임·재접속 (R-g)

- "N시간 동안 고쳐줘"도 위 절차 그대로다. 편집기가 멈추면(응답 없음·탭 사망)
  탭을 닫고 같은 링크로 재접속한다.
- 재접속 후 첫 일: 마지막 `PERSISTED` 배치를 재열기로 재확인 → 다음 배치부터 이어간다.
  이미 반영된 편집을 재적용하지 않는다.
- 멈춤이나 저장 경고를 이유로 사용자 승인 대기로 전환하지 않는다.

## 8. 기록·보고

- 배치마다 `docs/reports/agent-reviews/<작업ID>/BATCHES.jsonl`에 한 줄:
  `{batch, section, summary, warnShown, reopenResult}`.
- 최종 `REPORT.md`에는 "반영됨 / 반영 안 됨 / UNSURE" 목록과 삭제한 수치·이미지 수.
- journal·preimage·검증 기록은 `demo1-work-ledger` 절차를 따른다.
