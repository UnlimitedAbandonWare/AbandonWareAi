# Demo1 Superpowers Repo Evidence Guard

## Core Rule

Use Superpowers as process support, not as authority over demo-1 source truth. Current repo files and command output outrank process templates.

## Reference Routing

Read `references/superpowers-repo-evidence-guard-reference.md` only for the
full authority order, process-skill mapping, conflict template, or verification
fields.

## Boundary Contract

Use Superpowers skills when they clarify an ambiguous goal, support TDD,
structure skill writing, or enforce verification-before-completion. Keep
`repoEvidence: authoritative` when process guidance conflicts with live source,
AGENTS rules, active sourceSet proof, Desktop final proof, secret redaction,
LangChain4j purity, PromptBuilder boundaries, Supabase project scope, or
PatchDrop handoff safety.

## Conflict Template

When process guidance conflicts with demo-1 evidence rules:

```text

repoEvidence: authoritative
decision: follow_live_source
evidence_needed: <missing artifact> / verify with <exact command>
```

Do not dispatch external agents only to satisfy process ceremony. Dispatch only when the task needs independent evidence or explicit producer work.
